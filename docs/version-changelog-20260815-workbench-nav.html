1. 为什么改

旧方式和公司现在一样：在当前页 iframe 里改 location，返回用 history.back()。

旧问题

  • 工作台每个菜单是一个 iframe。点证券代码后，同一个 iframe 跳到详情，列表被盖掉。
  • 详情「返回」用 window.history.back()。
  • 多个 iframe 共用浏览器联合历史。先在「证券池查询」进详情，再在「主体历史」进详情，再回查询点返回，会退到别的页。
  • 兜底还写死跳到调库列表（如 security_pool_adjust.html），不是点进来的查询页。

本次目标

  • 列表 / 事宜页签保持不动。
  • 点代码、处理、查看、去调库：新开一个工作台 Tab。
  • 同一条记录再点：激活已有 Tab，并刷新内容。
  • 详情 / 审核「返回」：关掉当前动态 Tab，回到来源 Tab。
  • 脱离工作台单独打开 html 时，仍允许 location.href 兜底。

3. 两层约定

本仓库为了能新开 Tab，在「业务页」和「工作台外壳」之间加了一层。公司若也是工作台 iframe + 页内 href，按同样两层加即可。

业务页只调这些

  • window.RrsWorkbench.openDetailTab(opts)
  • window.RrsWorkbench.closeActiveTab()
  • window.RrsWorkbench.buildTabIndex(prefix, parts)
  • window.RrsWorkbench.formatDetailTitle(name, fallback, suffix)

定义在 js/api.js。找不到父窗口开 Tab 能力时返回 false。

工作台外壳必须提供

  • window.parent.RrsWorkbenchOpenTab(opts)
  • window.parent.RrsWorkbenchCloseActiveTab()，关掉才返回 true

本仓库在 index.html 的 Vue created 里挂上。公司工作台外壳也要加同等两个方法，否则业务页 openDetailTab 会失败并退回 location.href。

opts 字段（与改前 href 一一对应）：page 仍是原来的 html 文件名（如 security_pool_adjust_detail.html）；query 仍是原来拼在 ? 后面的参数；另外多了 index（页签唯一键，同键复用）和 title（页签标题）。本仓库登录用户仍由外壳 buildPageUrl 补，业务页 query 里不必再拼。

只改业务页、不改工作台外壳不够。外壳不提供 RrsWorkbenchOpenTab 时，会退回 location.href，和改前一样。

5. 核心代码对照（公司当前 = 改前）

下面都是本仓库真实改法。公司按文件搜同名方法，把「改前」换成「改后」。页内 currentPage = 'detail' 不要改成开 Tab。

例 1 · 新增公共适配器 js/api.js

改前：没有 window.RrsWorkbench。

改后（节选，完整见该文件）：

window.RrsWorkbench = {
    getHost() {
        try {
            if (window.parent && window.parent !== window
                && typeof window.parent.RrsWorkbenchOpenTab === 'function') {
                return window.parent;
            }
        } catch (e) {}
        return null;
    },
    buildTabIndex(prefix, parts) { /* 前缀 + 代码/批次拼唯一键 */ },
    formatDetailTitle(name, fallback, suffix) { /* 简称 + 详情/审核/调库 */ },
    openDetailTab(options) {
        const host = this.getHost();
        if (!host) return false;
        host.RrsWorkbenchOpenTab(options || {});
        return true;
    },
    closeActiveTab() {
        const host = this.getHost();
        if (!host || typeof host.RrsWorkbenchCloseActiveTab !== 'function') return false;
        return host.RrsWorkbenchCloseActiveTab() === true; // 没关掉动态 Tab 必须返回 false
    }
};

例 2 · 工作台外壳挂方法 index.html created

改前：

window.RrsWorkbenchOpenPage = index => this.openMenuItem(index);
this.openHomeTab();

改后：

window.RrsWorkbenchOpenPage = index => this.openMenuItem(index);
window.RrsWorkbenchOpenTab = options => this.openDynamicTab(options);
window.RrsWorkbenchCloseActiveTab = () => this.closeActiveDynamicTab();
this.openHomeTab();

外壳还要有 openDynamicTab（新开或同键 renderKey++ 刷新）、closeActiveDynamicTab（仅 tab.dynamic 为 true 才关，并返回 true/false）、关 Tab 后激活 fromIndex。

例 3 · 查询点代码 pages/security_pool_query.html → openSecurityAdjustDetail

不要把下面的 security-detail 套到主体/CRMW 上。主体用 openForbiddenPoolAdjustDetail + companyCode + forbidden-detail；禁投查询可能主体或证券两条详情；CRMW 用 openCrmwAdjustDetail + crmw-detail。

改前（公司当前）：

openSecurityAdjustDetail(row) {
    const params = new URLSearchParams();
    if (row.securityCode || row.windCode) params.set('securityCode', row.securityCode || row.windCode);
    if (row.targetPoolId) params.set('targetPoolId', row.targetPoolId);
    if (row.adjustBatchNo) params.set('adjustBatchNo', row.adjustBatchNo);
    params.set('entryMode', 'view');
    window.RrsAuth.appendUserParams(params);
    window.location.href = this.pagePaths.securityPoolAdjustDetail + '?' + params.toString();
}

改后：

openSecurityAdjustDetail(row) {
    const code = row.securityCode || row.windCode || '';
    const name = row.securityShortName || code;
    const params = new URLSearchParams();
    if (code) params.set('securityCode', code);
    if (row.targetPoolId) params.set('targetPoolId', row.targetPoolId);
    if (row.adjustLogId) params.set('adjustLogId', row.adjustLogId);
    if (row.adjustBatchNo) params.set('adjustBatchNo', row.adjustBatchNo);
    params.set('entryMode', 'view');
    const opened = window.RrsWorkbench.openDetailTab({
        index: window.RrsWorkbench.buildTabIndex('security-detail', [code, row.adjustLogId, row.adjustBatchNo, row.targetPoolId]),
        title: window.RrsWorkbench.formatDetailTitle(name, code),
        page: this.pagePaths.securityPoolAdjustDetail,
        query: params.toString()
    });
    if (opened) return;
    window.RrsAuth.appendUserParams(params);
    window.location.href = this.pagePaths.securityPoolAdjustDetail + '?' + params.toString();
}

6. 公司按同样方式改（不要理解成换路由）

公司代码 = 本仓库这次修改之前。跳转目标仍是原来的 html（security_pool_adjust_detail.html 等），不是另一套路由名。

公司要做的（和本次改动相同）

  • 公共脚本增加 window.RrsWorkbench（可直接对照 js/api.js）。
  • 工作台外壳增加开 Tab / 关 Tab（对照 index.html 的 openDynamicTab、closeActiveDynamicTab）。
  • 业务页把 location.href = 'xxx.html?' 换成 openDetailTab，page 仍写原来的 html 文件名。
  • 详情 / 审核 / 调整页返回先 closeActiveTab()。
  • 调整页读取 URL 里的证券 / 主体 / CRMW 代码并打开对应对象。

不要做成这样

  • 不要把 html 文件名改成公司路由常量、菜单编码（那是别的迁移专题，不是这次跳转改造）。
  • 不要只在业务页声明空的 window.RrsWorkbench，外壳不实现开 Tab。
  • 不要改页内 currentPage = 'list' / 'detail' 那种单页切换。
  • 不要改后端接口。

只改业务页、外壳不提供 parent.RrsWorkbenchOpenTab 时，openDetailTab 返回 false，后面的 location.href 仍会执行，和改前一模一样。

7. 给公司 AI 的提示词（可直接复制）

请按演示项目 znty-rrs-ui 本次「跨页跳转改新开 Tab」同样方式，修改本公司 RRS 前端。

重要前提：
- 公司当前代码 = 演示项目这次修改之前：查询/历史/我的事宜用 window.location.href 打开同名 html（如 security_pool_adjust_detail.html），返回用 history.back()。
- 跳转目标仍然是这些 html 文件，不要改成路由 name / 菜单编码，不要发明另一套开页 API。
- 不要改后端接口。
- 不要改调整页内部 currentPage='list'/'detail' 的单页切换。

请对照演示项目做这三层同样的改：
1. 公共脚本增加 window.RrsWorkbench（openDetailTab / closeActiveTab / buildTabIndex / formatDetailTitle）。openDetailTab 调 window.parent.RrsWorkbenchOpenTab；没有父窗口能力时返回 false，页面再走原来的 location.href。
2. 工作台外壳（类似 index.html）增加：RrsWorkbenchOpenTab 新开页签；同一 index 复用并刷新内容；RrsWorkbenchCloseActiveTab 只关动态详情/审核 Tab 且关掉才返回 true；返回后来源 Tab。
3. 业务页：搜 window.location.href 且目标是 *_detail.html / *_approve.html 的，改成 openDetailTab。方法名不要抄错：证券 openSecurityAdjustDetail（security-detail）；主体 openForbiddenPoolAdjustDetail（forbidden-detail + companyCode）；禁投查询 openPoolAdjustDetail（主体或证券）；CRMW openCrmwAdjustDetail（crmw-detail）。搜 history.back 的返回改成先 closeActiveTab。
4. 工作台外壳 openMenuItem 要能按 index 激活已经打开的动态 Tab；侧栏高亮用 fromIndex。iframe 需要能按 tab.index 找到，以便切回来源页时回调 RrsPageOnShow（仅我的事宜需要刷新）。
5. 公司若无「分级规则提醒 / 去调库」，不必强行给调整页加 URL 入参；若有带 securityCode/companyCode/crmwScode 打开调整页的入口，再按例 6 改。

目标行为：
1. 点证券代码/简称、我的事宜处理/查看、去调库：新开一个 Tab，来源列表 Tab 不要被盖掉。
2. 同一业务键再点：激活已有 Tab 并刷新，不要再开一个。
3. 详情/审核返回：关闭当前动态 Tab，回到来源 Tab。
4. 从「去调库」打开的调整页，返回关 Tab；从菜单进入的调整页，返回仍回页内列表。

page 继续用原来的 html 文件名。query 继续用：
securityCode / companyCode / crmwScode / adjustLogId / adjustBatchNo / targetPoolId / entryMode

调整页需读取这些 URL 参数并打开对应对象：
- security_pool_adjust：securityCode
- forbidden_pool_adjust：companyCode 走主体；仅 securityCode 走 ABS
- crmw_pool_adjust：crmwScode + securityCode

搜索关键词：window.location.href、history.back、security_pool_adjust_detail.html、_approve.html、entryMode。

8. 注意点 / 刻意没做的

  • 只覆盖研究管理跨页跳转。文档管理、版本说明、脚本工具未改。
  • 证券 / 禁投 / CRMW 调整页内部列表进详情仍是 currentPage，不是新 Tab。
  • 左侧「审核详情」菜单打开的空审核/详情页不是动态 Tab；公司计划隐藏该菜单，可不处理。
  • 未做 Tab 数量上限；详情 iframe 较重，连点很多条会占内存。
  • 查询 / 历史列表回来不会自动刷新，只有「我的事宜」注册了 window.RrsPageOnShow。
  • 查询无批次、历史有批次时，同一券可能开两个详情 Tab（key 不同），本次未合并。
  • 菜单「证券池调整」和提醒「去调库」是两个 Tab（security-adjust vs security-adjust-代码）。

验收：工作台打开证券池查询，点券 A、券 B 应出现两个详情 Tab，查询 Tab 还在；再点券 A 只激活并刷新。我的事宜点处理应新开审核 Tab；返回后事宜列表还在且角标会更新。去调库应打开该券调整详情，返回关 Tab 回事宜。
