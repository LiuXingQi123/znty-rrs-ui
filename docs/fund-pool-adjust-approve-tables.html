基金池调库审核与详情

基金调库审核和详情逐块沿用证券池调库审核、详情的页面结构与样式：顶部栏、可折叠信息卡片、当前池摘要及展开表格、调库记录、原因和建议、当前流程状态，以及固定底部操作栏。仅将证券业务字段替换为基金字段，基金报告和其他材料仍支持下载。

页面功能

「审核审批」标题右侧同行显示「当前步骤：步骤名称」，复用「流程名称」的 el-tag size="mini" type="info" 标签样式；内容区全宽展示处理意见。没有当前用户待处理步骤时，标题旁不显示步骤名称。

  • 审核页展示基金基础信息、当前所在池、调库记录、原因和建议、当前流程状态及审核审批区。审核页和详情页的调库记录字段顺序统一为：基金代码、投资池名称、调整类型、调整方向、调整原因、基金报告、其他材料、提交时间、审批流程、审核状态，不展示序号和申请人。
  • 审核页和详情页的当前流程状态均与证券池调库详情一致，表格字段顺序为：步骤名称、步骤结果、开始时间、处理人、处理结果、处理时间、处理意见，并保留节点合并、当前处理人强调及行状态样式。
  • 审核审批区展示当前步骤和处理意见，去掉处理结果/审核结果单选项。固定底栏保留导出 PDF、返回，并通过独立操作按钮决定方向：修改阶段为「提交」（approve）和「终止流程」（reject），普通审核阶段为「通过」和「驳回」。驳回或终止流程必须填写意见并二次确认，取消确认不提交；处理期间两个操作按钮均禁用。
  • 详情页在原因和建议后展示当前流程状态，提供相同业务上下文的只读展示。固定底栏右侧提供导出 PDF 和返回操作，导出范围及打印后恢复折叠状态的方式与证券池调库详情保持一致。
  • 页面以 fundCode 和 adjustLogId 或 adjustBatchNo 定位业务记录；缺少入口参数时通过 Element UI 顶部警告消息提示从业务页面进入。

接口

申请处于驳回待修改（audit_status=11），且当前用户可处理发起人修改待办（pending、initiator）时，调整原因和意见可编辑；重新提交时携带 adjustReason、adjustAdvice。后端校验修改节点路由、驳回状态和原发起人身份，管理员沿用代办权限，并只更新当前待办所属批次。未传字段保持原值，空字符串允许清空；普通审批、只读详情和终止流程不保存这两项修改。

接口说明
/api/v1/fundPoolAdjust/queryFundDetail基金只读基础信息
/api/v1/fundPoolAdjust/queryFundPoolStatus当前有效基金池状态
/api/v1/fundPoolAdjust/queryAdjustLogList批次调库记录
/api/v1/fundPoolAdjust/queryAdjustStepList审批步骤列表
/api/v1/fundPoolAdjust/submitAdjustAudit审批处理与流程推进

状态落库

只有最终审批通过的批次状态为 20 并写入基金当前池状态表 ip_pool_status_fund。其他审核状态仅保存在基金日志和步骤表中。
