业务流程总览

基金审核页与只读详情共用批次、步骤和附件视图，按处理权限推进一般流程；最终审批通过后写入基金当前池状态。

1. 定位基金批次按基金代码、日志ID或批次号打开审核或详情。
2. 加载申请资料读取主档、当前池、批次日志、步骤和附件。
3. 核验权限与状态识别本人待处理步骤、管理员接管和驳回修改阶段。
4. 审批或修改重提通过、驳回，或修改阶段提交、终止流程。
5. 更新并返回事务推进步骤和状态，最终20落池并刷新来源页面。

查询、校验与操作逻辑

页面显示与业务权限分开校验；详情只读，审核按当前有效步骤提供操作。

POST /api/v1/fundPoolAdjust/queryFundDetail · queryFundPoolStatus · queryAdjustLogList · queryAdjustStepList · submitAdjustAudit

页面加载 / 查看模式

  • fundCode 定位基金，可携带 adjustLogId / adjustBatchNo / targetPoolId 定位本次申请；不传批次的日志查询仅取流程中记录。
  • 分别读取基金只读主档、有效当前池、批次日志、审批步骤及材料；只读详情不提供审批动作。
  • 调整记录展示基金代码、池、类型、方向、原因、基金报告、材料、提交时间、流程和状态；不增加序号、申请人列。

并发与权限

  • 普通用户只能处理本人有效 pending 步骤；服务核验日志、批次、步骤、处理人和当前状态，防止过期或重复处理。
  • 管理员ID为1或10000～10100，可接管处理，优先使用本人步骤；入口可见名单不替代审批权限。
  • 按钮提交期间两项动作均禁用，仅点击项显示加载；处理成功返回业务页签并刷新来源页。

会签与抢占

  • 按快照保留一般流程的会签、抢占等处理机制；抢占完成后其他同节点待处理步骤按规则跳过。
  • 步骤表展示节点名称、步骤结果、开始时间、处理人、处理结果、处理时间和意见，合并节点信息并突出当前处理人。
  • 当前步骤标签放在审批标题旁；不设置“结果”单选框，使用明确的通过/驳回动作。

修改后重提

  • 审核状态11或步骤名称含“修改”时进入修改阶段；按钮显示“提交 / 终止流程”，其他审批显示“通过 / 驳回”。
  • 只有原发起人或管理员且具有当前修改待办时可编辑本批次原因、建议，每项最多1000字。
  • 重提发送修改文本；未传字段保持原值，传空字符串清空。终止不保存未提交文本；文本与流程更新同事务。

流程结束与状态落库

  • 请求包含 adjustLogId / adjustBatchNo / stepId / processAction / processComment / handlerId / handlerName；动作使用 approve 或 reject。
  • 驳回或终止需填写处理意见并确认；服务按流程配置决定退回修改或结束。
  • 最终审批通过状态20才新增调入状态或软删除调出状态；11/21/99仅更新日志和步骤，不改当前池。

附件、报告与 PDF

  • 附件列表指定 businessDomain=fund 及 adjustLogIds，按附件ID下载；基金报告、其他材料分别展示。
  • 材料关联 ip_adjust_log_fund，保留手工/内部/外部的基金专属分类。
  • PDF 复用通用导出，排除页面操作控件、基金调库输入项、调整原因和建议；只读资料与审批轨迹用于留档。
  • 审核页和详情页导出 PDF 时，调库记录的「调整类型」「调整方向」「审核状态」表头与标签复用债券研究的竖排打印样式，居中显示，避免超出单元格；普通页面仍保持横排。

业务入口与处理范围

审核、详情和我的事宜使用同一基金业务上下文，临时代码规则影响节点处理方式。

入口与业务域

  • fund_pool_adjust_approve.html 承担当前步骤办理；fund_pool_adjust_detail.html 展示只读详情。
  • 我的事宜已接入 fund 业务；业务入口名单只决定首次页面加载时是否显示入口，不作为后端审批授权。
  • 基金池查询和历史名称、代码链接携带对应日志、批次、目标池参数打开详情。

临时基金与 O32

  • 有效 temporary 登记命中的基金 O32 节点转人工 pending；普通正式基金的 O32 自动或常规处理保持配置行为。
  • 人工转正只改00/11在途日志中的基金代码和正式资料，保留原步骤、批次和附件，终态日志不改。
  • 取消发行停用临时主档但不自动清理业务引用，后续审批可能受阻；完整分支见 基金临时代码管理。

涉及表、用途与触发场景

按本模块实际执行阶段标注读写；表组内具体表的作用见用途与触发场景。

表名用途读写触发场景
rrs_fundinfo基金主档、名称、类型与只读基础信息。查询查询候选基金、打开详情、校验和提交时重新读取权威主档。
ip_investment_pool投资池层级、基金范围、容量、锁池、报告限制及一般流程配置。查询加载池树或目标池、回填完整池路径、执行调入调出校验。
ip_pool_status_fund基金当前池及最终审批结果。查询新增更新页面只读有效状态；最终审批20时执行调入新增或调出软删除。
ip_adjust_log_fund当前批次申请资料、流程信息及审核状态。查询更新加载批次，驳回修改时更新原因建议，审批推进时更新审核状态。
ip_adjust_step_fund基金批次节点、处理人及处理记录。查询新增更新提交建立开始、发起和待处理步骤；审批推进、会签、驳回与重提时读写。

wf_node_approval_config / wf_node_approval_handler一般审批节点策略与配置处理人。查询读取发布版本的审批配置和处理人，识别人工、自动及 O32 策略，生成或推进步骤。

rrs_temp_fund_code基金临时代码登记。查询按 temporary 状态识别临时基金，将其 O32 节点转人工待处理。

关键规则与当前实现说明

  • 最终审批通过是池状态生效条件；详情展示的历史申请状态不等于基金当前仍在该池。
  • 最终通过落池前锁定基金主档，重新校验基金有效性、当前池状态、容量、池关系、开放日和冻结期；在途检查排除当前批次，校验失败不落池。
  • 审批动作必须以服务端当前步骤和处理权限为准，前端隐藏按钮不能代替服务校验。
  • 驳回待修改的资料更新、审批日志和步骤推进同事务，任何失败均回滚。
  • 基金申请规则见 基金池调整申请；批量和 Excel 申请进入同一基金审批链路。
审核与详情共用资料展示，处理动作只对当前具有资格的待处理步骤开放。
