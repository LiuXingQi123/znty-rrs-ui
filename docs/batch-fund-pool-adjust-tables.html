业务流程总览

先选目标投资池，再选多只基金，统一填写调库资料并逐基金校验，使用一般流程提交独立基金批次。

1. 选择目标池查询当前用户可调整的启用基金叶子池，选择调入或调出。
2. 勾选多只基金按代码、简称、品种和管理人筛选并跨页选择。
3. 填写共用资料统一填写基金评分、投资类型、分管领导审批及附件。
4. 逐基金校验扩展关联项，展示整组通过或失败及可选一般流程。
5. 提交并审批有效组整批事务提交；最终审批通过才更新基金池状态。

目标池与候选基金查询

目标池选择范围与候选基金查询均受基金业务和当前用户权限约束。

POST /api/v1/batchFundPoolAdjust/queryPoolPage · queryFundPage

目标池查询

  • 读取启用、未删除、基金范围的叶子投资池，并限制为当前用户具有调整权限的池。
  • 展示投资池层级、名称、配置和当前基金数量；数量只统计未删除且 audit_status=20 的基金池状态。
  • 选定池后选择 in / out 方向；服务转换为内部“调入 / 调出”值。

候选基金查询与筛选

  • 候选主表为 rrs_fundinfo，关联有效基金品种字典，排除已终止或退市基金。
  • fundCode / fundShortName 模糊查询，securityType 品种匹配，fundAdministrator 管理人筛选。
  • 调入候选排除已在目标池基金；调出候选只包含目标池内有效基金。
  • 支持分页和跨页勾选；列表与单笔基金申请的基金基础字段保持一致。

批量校验与提交

复用单基金调库校验，基金手工项与其关联项组成不可拆分的校验组。

POST /api/v1/batchFundPoolAdjust/checkAdjust · addAdjustLog · addAdjustLogWithFiles

逐基金校验与页面展示

  • 评分 fundScore、投资类型 fundInvestmentType、分管领导审批 needRiskLeaderApproval 为所有勾选基金共用的必填资料。
  • 资料可在选择和确认步骤编辑，返回上一步保留已填值；页面不提供“放开规则”。
  • 逐只调用基金通用调库校验，检查主档、权限、锁池、当前状态、容量、在途申请、重复、开放日、冻结期及报告要求。
  • 一只基金的手工项或任一关联项失败时整组失败；允许只提交其余有效基金组，互斥产生的反向项保持原方向。

提交和审批

  • 仅接受服务返回的完整关联组，以及该组允许的一般流程；不注入快速或批量流程。
  • 按主档 ID 顺序加锁，所有组先完成复核，再创建流程，避免本次新申请相互阻塞。
  • 每只基金独立一个 FUND 批次，手工项与关联项共批次；fundCount 为基金数，submitCount 为日志项数。
  • 所有有效组使用外层事务；任一提交失败整体回滚。提交仅生成状态00日志及步骤，最终20才落池。

共用资料与附件绑定

共用输入按每只基金生成申请资料，材料文件按各手工主日志关联。

必填字段与文本

  • 基金评分为数值，0有效；数据库 DECIMAL(10,4)，最多6位整数、4位小数。
  • 投资类型为 stock / equity_hybrid / money_market / bond_hybrid / other；领导审批为 0 / 1。
  • 三字段只采集，不参与入池规则和流程节点判断；复制到手工及关联日志。调整原因和建议为可选，页面各限500字。

报告与其他材料

  • 按目标池报告限制上传或选择报告，基金分类与单笔申请一致。
  • 共享文件物理上传一次，分别绑定各基金手工主日志，关联日志不重复绑定共享材料。
  • 提交的原始文件名列表必须与文件顺序、数量一致；不一致明确失败。

ip_adjust_step_fund基金批次节点、处理人及处理记录。查询新增更新提交建立开始、发起和待处理步骤；审批推进、会签、驳回与重提时读写。
wf_flow_definition / wf_flow_version / wf_flow_node / wf_flow_edge一般流程定义、已发布版本、节点与连线。查询选择一般流程并生成申请流程快照；本模块不提供快速或批量流程选项。
wf_node_approval_config / wf_node_approval_handler一般审批节点策略与配置处理人。查询读取发布版本的审批配置和处理人，识别人工、自动及 O32 策略，生成或推进步骤。

rrs_report_in / rrs_report_out内部、外部报告资料。查询申请时选择报告来源并按投资池报告限制校验。
rrs_temp_fund_code基金临时代码登记。查询按 temporary 状态识别临时基金，将其 O32 节点转人工待处理。

关键规则与当前实现说明

  • 每只基金独立审批批次，整批提交的事务原子性不意味着所有基金共用一个流程。
  • 来源/调入/调出/弹性等限制沿用基金单笔校验；不引入债券到期、主体评级、担保人或基金评分区间规则。
  • 共同材料只绑定手工主日志；基金专属报告和材料分类见 基金池调整申请。
  • 临时基金 O32 节点转人工待处理；后续转换为正式代码不会自动办结已有步骤。
批量校验允许剔除失败的基金组；提交阶段任一运行错误都会回滚本次全部有效组。
