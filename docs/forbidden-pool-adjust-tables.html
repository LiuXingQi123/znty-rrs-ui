禁投池调整

页面列表区双 Tab：主体 / ABS债。主体链路以发行主体为调整对象（Wind 主体表），对手工限定池债券禁止库(15)/观察池(16)/黑名单质押库(17)/重点观察名单(23)调入/调出；仅目标为债券禁止库(15)且主体生效（20）时同步旗下未到期债券（含 ABS/crmw）；ABS 链路以 ABS 证券为对象，独立 API 前缀 /api/v1/forbiddenAbsPoolAdjust，交互对齐证券池单笔调库（列表 → 选池 → 校验提交）。仅 audit_status=20 落地池状态。

业务流程总览

前端 pages/forbidden_pool_adjust.html：listTab=company|abs；主体详情页 currentPage=detail，ABS 详情页 currentPage=absDetail（步骤 absAdjustStep 1/2）。状态字段主体与 ABS 完全隔离，禁止复用同名 data。

1. 列表双 Tab主体：查 wind_cbondissuer；ABS：查 ABS 证券分页（证券代码/简称/发行人）。
2. 加载详情主体/ABS 详情、当前在池、可调池树（债券禁止库等四池）。
3. 校验调整主体或 ABS 各自 checkAdjust + 联动互斥 + 流程。
4. 提交审批multipart 附件；主体 company / ABS 证券级写日志。
5. 生效仅 20 落池；仅债券禁止库另同步旗下未到期债（含 ABS/crmw）。

ABS债 Tab 与接口

ABS 交互参考证券池调库：列表 → 详情选池(step1) → 校验提交(step2)。后端独立前缀，附件/报告仍走通用接口。

POST /api/v1/forbiddenAbsPoolAdjust/querySecurityPage · querySecurityDetail · queryAdjustPoolList · querySecurityPoolStatus · checkAdjust · addAdjustLog（JSON）· addAdjustLogWithFiles（multipart）· queryAdjustLogList · queryAdjustStepList · queryLastCreditReport（可选）· queryRedirectPoolOptions（改判池，审批页用）

前端状态与页面

  • 列表筛选：absSearchForm（securityCode / securityShortName / issuer）；表格 absTableData + absPagination。
  • 详情：只读证券基本信息 absBondDetail；当前证券/主体所在池；可调入/可调出双栏树 absInPools / absOutPools。
  • 步骤：absAdjustStep 1 选池、2 校验结果 absAdjustReviewList + 原因建议；从 absDetail 返回保持 listTab='abs'。
  • 附件与报告映射：absAttachmentFiles / absCreditReportSelections 等，与主体侧隔离；报告弹窗通过 reportDialogContext 分流。

接口与池范围

  • API 前缀：/api/v1/forbiddenAbsPoolAdjust；附件 /api/v1/attachments/*，报告 /api/v1/reports/*。
  • 可调池后端只返回手工目标池债券禁止库(15)/观察池(16)/黑名单质押库(17)/重点观察名单(23)（与主体限定池一致），前端按当前在池过滤调入/调出树并做互斥替换。
  • 校验 checkAdjust、提交 addAdjustLogWithFiles（multipart request + files）与证券池单笔同构。
  • 可选预填：详情加载后调用 queryLastCreditReport 回填信评报告。

主体查询与池状态

主体主数据来自跨库 Wind 表，不依赖 rrs_securityinfo 的 company 行；旗下债券经 issuer_code 关联。

POST /api/v1/forbiddenPoolAdjust/queryCompanyPage · queryCompanyDetail · queryCompanyPoolStatus · queryCompanyBondList · queryAdjustPoolList · queryAdjustLogList · queryAdjustStepList

主体与债券

  • 列表/详情：ais_inv_ods.wind_cbondissuer（used=1），代码 s_info_compcode；筛选代码/名称/行业。
  • 旗下债券数量（主数据总数）：issuer_code + category_type=bond（含 crmw）。
  • 旗下债券在池：普通池 ip_pool_status + CRMW 池 ip_pool_status_crmw（按 crmw_scode）；分组 bondCount 为该池在池数。
  • 旗下债券明细：queryCompanyBondList 与对应池 bondCount 条数一致（同样含 CRMW）。

可调整池

  • 接口 POST .../queryAdjustPoolList 实际调用 queryCompanyAdjustPoolList：硬编码 ALLOWED_MANUAL_POOL_IDS = {15,16,17,23}（演示库语义：禁投池/观察池/黑名单质押库/重点观察名单），四池须均存在且启用，缺一即报错。
  • 校验/提交时手工项 targetPoolId 必须属于上述集合，否则拒绝（与可选池同源）。
  • 非管理员再按 adjustable 权限过滤；返回互斥、容量与层级；in/out 两次请求返回同一四池集合，前端按主体当前在池状态生成调入/调出树。
  • 不走信用债主体内评×期限矩阵（目标池非 credit_bond，对象为 company）。

校验、提交和审批

主体级流程与证券池调库同构；调库类型固定 company，生效后增加旗下债券同步。

POST /api/v1/forbiddenPoolAdjust/checkAdjust · addAdjustLog（JSON）· addAdjustLogWithFiles（multipart）· /api/v1/forbiddenPoolAdjustFlow/submitAdjustAudit（JSON）· submitAdjustAuditWithFiles（multipart）

校验与申请

  • 主体跳过品种/市场校验；保留池锁定、待处理（pending）、重复入/未入池、容量、来源/限制、互斥冲突、全局禁止池、行业、开放日等。
  • 弹性禁投池（soft_restrict）写 warnings 不阻断；互斥配套调出失败反阻断同组手工调入。
  • 自动扩展调入联动（in_linked）/调出联动（out_linked）/调入互斥（in_mutex）调出项；手工项选流程，自动项继承同组流程与批次。
  • 前端调整说明失败时「调整说明」分条展示「未通过（共 N 项）」+ 编号列表（保留全部 failReasons，检查项文案不含「无法调入」终局语气）；同组行底色区分；提交期间用 submitLoading 布尔禁用按钮防重复（无时间窗冷却）。
  • 直通：先锁池复核再落池并 syncCompanyBonds；非直通写 ip_adjust_step，仅最终审批通过（20）落池。

主体级生效（syncCompanyBonds）

  • 先写/软删主体 ip_pool_status；仅目标池=债券禁止库(15) 时再同步旗下债。
  • 调入：未到期、bond 大类（含 ABS/crmw）、尚不在目标池 → 自动调入日志 + 入池。
  • 调出：未到期、bond 大类（含 ABS/crmw）、当前在目标池 → 自动调出日志 + 软删在池。
  • 观察池 / 黑名单质押库 / 重点观察名单：只落主体，不同步旗下债。
  • 自动日志与主体共用 submit_time / 批次语义，便于历史同批聚拢；驳回/终止不改池、不同步债券。

关键规则与当前实现说明

  • 页面列表 主体 | ABS债 双 Tab；主体逻辑与 ABS 状态字段隔离（ABS 使用 abs* 前缀 data）。
  • 主体调库日志 security_type 固定为 company；对象代码为 Wind 主体码（s_info_compcode），不是债券 wind_code；主体主数据读 ais_inv_ods.wind_cbondissuer。
  • ABS 调库走 /api/v1/forbiddenAbsPoolAdjust/*，对象为 ABS 证券代码；可调池同样限定债券禁止库(15)/观察池(16)/黑名单质押库(17)/重点观察名单(23)。
  • 主体级校验跳过品种、市场、债券到期；保留池锁定、pending、重复入/未入池、容量、来源/限制、互斥、全局禁止、行业、开放日等。
  • 主体生效后仅债券禁止库同步旗下债：未到期 + bond 大类（含 ABS/crmw）；调入还要求未在目标池，调出要求当前在目标池。其它手工风险池只落主体。
  • 债券自动同步日志为大类 bond，会出现在禁投池历史中，但不会进入「主体池调整历史」（按 company 过滤）。
  • 仅 audit_status=20 落地主体与债券池状态；驳回/撤回等只改日志与步骤。
  • 发起人不能参与后续审批节点，管理员和发起/修改语义节点除外；会签全员完成，抢占跳过同节点其他待办。
  • 修改节点通过 resubmit 重新提交；附件变更仅允许修改节点重提。
  • 已知实现风险：目标池依赖固定债券禁止库(15)/观察池(16)/黑名单质押库(17)/重点观察名单(23)，跨环境主键不一致会失效（见业务问题/新老对比文档）。
本页依据当前 Controller、Service、Mapper XML、需求文档 15/16/17 和前端调用链整理；后续代码规则变化时应同步维护。
