禁投池调整

页面列表区双 Tab：主体 / ABS债。主体链路以发行主体为调整对象（Wind 主体表），对手工限定池债券禁止库(15)/观察池(16)/黑名单质押库(17)/重点观察名单(23)调入/调出；仅目标为债券禁止库(15)且主体生效（20）时同步旗下未到期债券（含 ABS/crmw）；ABS 链路以 ABS 证券为对象，独立 API 前缀 /api/v1/forbiddenAbsPoolAdjust，交互对齐证券池单笔调库（列表 → 选池 → 校验提交）。仅 audit_status=20 落地池状态。

业务流程总览

前端 pages/forbidden_pool_adjust.html：listTab=company|abs；主体详情页 currentPage=detail，ABS 详情页 currentPage=absDetail（步骤 absAdjustStep 1/2）。状态字段主体与 ABS 完全隔离，禁止复用同名 data。

1. 列表双 Tab进入页面时并行预载主体和 ABS 两个列表，切换 Tab 只重排表格、不重复查询；主体查 wind_cbondissuer，ABS 查 ABS 证券分页。
2. 加载详情主体/ABS 详情、当前在池、可调池树（债券禁止库等四池）；主体调库日志附件按日志 ID 去重后一次批量查询，并按返回的 mainId 回填。
3. 校验调整主体或 ABS 各自 checkAdjust + 联动互斥 + 流程。
4. 提交审批multipart 附件随 files 传同序 originalFileNameListJson 以保留中文原始文件名；主体 company / ABS 证券级分别写日志。
5. 生效仅 20 落池；仅债券禁止库另同步旗下未到期债（含 ABS/crmw）。

ABS债 Tab 与接口

ABS 交互参考证券池调库：列表 → 详情选池(step1) → 校验提交(step2)。后端独立前缀，附件/报告仍走通用接口。

POST /api/v1/forbiddenAbsPoolAdjust/querySecurityPage · querySecurityDetail · queryAdjustPoolList · querySecurityPoolStatus · checkAdjust · addAdjustLog（JSON）· addAdjustLogWithFiles（multipart）· queryAdjustLogList · queryAdjustStepList · queryLastCreditReport（可选）· queryRedirectPoolOptions（改判池，审批页用）

前端状态与页面

  • 列表筛选：absSearchForm（securityCode / securityShortName / issuer）；表格 absTableData + absPagination。列对齐证券池调库主列表：在操作列前由前端展示是否担保（guarantFlag=1）、是否含权（inrightFlag=1）、是否永续（yxFlag=1）、是否私募（发行方式或内部分类含「私募」）、是否ABS（absFlag=1 或类型 abs；abs_all 不算）、是否次级（cjFlag=1）；后端 SELECT si.* 原样返回，不做中文映射；详情页证券基本信息不增加这些字段。
  • 详情：证券基本信息 absBondDetail 与证券池调库字段/交互对齐（步骤1可编辑、步骤2只读）；担保人下拉仅按代码、名称两个逗号串的位置配对，全部代码通过一次 queryGuarantorGradeList 查询 ais_inv_analysis.v_inv_grade_result，按 windcode 匹配最新 totalScore，缺失评分显示空白；左侧显示担保人、右侧显示内评，选中后只读展示且不覆盖主数据评分串；当前证券/主体所在池；可调入/可调出双栏树 absInPools / absOutPools。
  • 步骤：absAdjustStep 1 选池、2 校验结果 absAdjustReviewList + 原因建议；从 absDetail 返回保持 listTab='abs'。
  • 附件与报告映射：absAttachmentFiles / absCreditReportSelections 等，与主体侧隔离；报告弹窗通过 reportDialogContext 分流。

接口与池范围

  • API 前缀：/api/v1/forbiddenAbsPoolAdjust；附件 /api/v1/attachments/*，报告 /api/v1/reports/*。
  • 列表/校验强制 abs_flag=1（仅 ABS 债）；可调池同样限定 15/16/17/23，前端按在池状态生成调入/调出树。
  • 校验 checkAdjust、提交 addAdjustLogWithFiles 与证券池单笔同构；不做主体级 syncCompanyBonds（不同步同主体其它债）。
  • 事宜场景：ABS 债 category_type≠company，待办归证券审核页（见我的事宜文档），不进主体禁投审核。
  • 可选预填：详情加载后调用 queryLastCreditReport 回填信评报告。

主体查询与池状态

主体主数据来自跨库 Wind 表，不依赖 rrs_securityinfo 的 company 行；旗下债券经 issuer_code 关联。

POST /api/v1/forbiddenPoolAdjust/queryCompanyPage · queryCompanyDetail · queryCompanyPoolStatus · queryCompanyBondList · queryAdjustPoolList · queryAdjustLogList · queryAdjustStepList

主体与债券

  • 列表/详情：ais_inv_ods.wind_cbondissuer（used=1），代码 s_info_compcode；筛选代码/名称/行业。
  • 旗下债券数量（主数据总数）：与证券池调整列表同口径——issuer_code + category_type=bond，排除 crmw 与 security_status=D（company 本就非 bond）。对比证券池时用主体全称填「发行人」；禁投侧按主体代码精确统计。
  • 旗下债券在池：普通池 ip_pool_status + CRMW 池 ip_pool_status_crmw（按 crmw_scode）；分组 bondCount 为该池在池数。
  • 旗下债券明细：queryCompanyBondList 与对应池 bondCount 条数一致（同样含 CRMW）。

可调整池

  • 接口 POST .../queryAdjustPoolList 实际调用 queryCompanyAdjustPoolList：硬编码 ALLOWED_MANUAL_POOL_IDS = {15,16,17,23}（演示库语义：禁投池/观察池/黑名单质押库/重点观察名单），四池须均存在且启用，缺一即报错。
  • 校验/提交时手工项 targetPoolId 必须属于上述集合，否则拒绝（与可选池同源）。
  • 非管理员再按 adjustable 权限过滤；返回互斥、容量与层级；in/out 两次请求返回同一四池集合，前端按主体当前在池状态生成调入/调出树。
  • 不走信用债主体内评×期限矩阵（目标池非 credit_bond，对象为 company）。

校验、提交和审批

主体级流程与证券池调库同构；调库类型固定 company，生效后增加旗下债券同步。

POST /api/v1/forbiddenPoolAdjust/checkAdjust · addAdjustLog（JSON）· addAdjustLogWithFiles（multipart）· /api/v1/forbiddenPoolAdjustFlow/submitAdjustAudit（JSON）· submitAdjustAuditWithFiles（multipart）

校验与申请

  • 主体跳过品种/市场校验；保留池锁定、待处理（pending）、重复入/未入池、容量、来源/限制、互斥冲突、全局禁止池、开放日等。
  • 行业限制：inCheckIndustry 方法保留，但 checkCommonIn 中调用已注释，当前不校验。
  • 弹性禁投池（soft_restrict）写 warnings 不阻断；互斥配套调出失败反阻断同组手工调入。
  • 自动扩展调入联动 / 调出联动 / 调入互斥调出项；手工项选流程，自动项继承同组流程与批次。
  • 前端调整说明失败时分条展示 failReasons；同组行底色区分；提交用 submitLoading 防重复。
  • 直通 / 终审：锁池 + recheckBeforeFinalApproval（动态子集，见下）后落池；主体通过后按规则 syncCompanyBonds。仅最终 audit_status=20 落池。

校验分层（check / 终审 recheck）

  • checkAdjust：全量通用规则（主体跳过品种/市场）+ 联动互斥扩展 + 流程候选；行业已注释；开放日/pending 在 check 阶段执行。
  • submit / 直通：不整单重跑 check；直通项走 recheck 子集再落池。
  • recheckBeforeFinalApproval（主体）：锁目标池后——调入：池锁 / 已在目标池 / 来源 / 限制 / 全局禁止 + 容量（含同批同步债预占）；调出：池锁 / 未在目标池 / 限制 / 冻结。不再跑：pending、同请求互斥、弹性警告、开放日、行业等。
  • ABS 链路 recheck 另含品种等证券向子集，与主体略有差异；分层意图与证券池调库一致。

主体级生效（syncCompanyBonds）

  • 先写/软删主体 ip_pool_status；仅目标池=债券禁止库(15) 时再同步旗下债。
  • 调入：未到期、bond 大类（当前含 ABS/crmw）、当前不在目标池 → 自动调入日志 + 入池。
  • 调出：未到期、bond 大类（含 ABS/crmw）、当前在目标池 → 自动调出日志 + 软删在池。
  • 观察池 / 黑名单质押库 / 重点观察名单：只落主体，不同步旗下债。
  • 新老差异：老系统同步常排除 ABS 板块；新系统 SQL 含 ABS/crmw（见 禁投池调整新老对比）。驳回/终止不改池、不同步债券。
  • 自动日志与主体共用 submit_time / 批次语义，便于历史同批聚拢。

关键规则与当前实现说明

  • 页面列表 主体 | ABS债 双 Tab；首次进入及带主体/证券代码进入时均并行预载两边列表，切换 Tab 不重新请求。主体逻辑与 ABS 状态字段隔离（ABS 使用 abs* 前缀 data）。初始化 applyUrlCompanyOrList：URL 有 companyCode 进主体详情，仅有 securityCode 切 ABS Tab。
  • 主体调库日志 security_type 固定为 company；对象代码为 Wind 主体码（s_info_compcode），不是债券 wind_code；主体主数据读 ais_inv_ods.wind_cbondissuer。
  • ABS 调库走 /api/v1/forbiddenAbsPoolAdjust/*，仅 abs_flag=1；可调池 15/16/17/23；不同步同主体其它债。
  • 主体级校验跳过品种、市场、债券到期；保留池锁定、pending、容量、来源/限制、互斥、全局禁止、开放日等；行业校验调用已注释。
  • check 全量 vs 终审 recheck 动态子集见上「校验分层」；仅 audit_status=20 落池。
  • 主体生效后仅债券禁止库(15)同步旗下债：未到期 + bond 大类（新含 ABS/crmw，老系统常排 ABS）；其它手工风险池只落主体。
  • 债券自动同步日志为大类 bond，会出现在禁投池历史，但不会进入「主体池调整历史」（按 company 过滤）。
  • 发起人不能参与后续审批节点（管理员与发起/修改语义节点除外）；会签全员完成，抢占跳过同节点其他待办。
  • 修改节点 resubmit；附件变更仅允许修改节点重提。
  • 已知风险：目标池依赖固定 ID 15/16/17/23，跨环境主键漂移会失效（见业务问题/新老对比）。
