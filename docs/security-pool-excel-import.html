业务流程总览

前端 pages/security_pool_excel_import.html：上方导入参数与上传，下方「导入明细 / 调库校验结果」双 Tab。API 前缀 /api/v1/securityPoolExcelImport。

主体导入的校验结果使用主体主数据中的全称，手工项（含校验失败项）和主体联动项口径一致；债券互斥项保留债券自身简称。名称为空时留白，不以代码代替。修复前已校验的批次需点击「重新校验」更新结果。

1. 导入参数默认主体，可切换证券。选择调入或调出，并填写本批调整信息。
2. 下载并上传按类型下载模板后拖入 xls/xlsx；解析父池/子池名称写入临时表。
3. 导入明细选择担保人/权益人，ABS 可自选权益人；查看内评后校验。
4. 调库校验证券集中取数后逐行执行共用规则，主体走 checkCompanyAdjust，结果分别展示。
5. 选流程提交弹窗与批量调库一致；确认后写申请/步骤，仅 20 落池。

导入参数与上传

方向与选项作用于整批；目标池不在页面选择，由 Excel 父池名称 + 子池名称解析。

POST /api/v1/commonFile/downloadTemplate · /api/v1/securityPoolExcelImport/uploadExcel

导入类型与选项

  • 导入类型：security 证券 / company 主体；调整方向：in 调入 / out 调出。
  • 调整原因、调整意见均为选填，整批共享，写入临时主表 fld002 / fld003。
  • 「清空目标池」独立于导入。点击按钮打开弹窗，在查询区使用投资池树设置筛选条件，点击「查询」应用，点击「重置」恢复全部可操作投资池。结果分页显示序号、投资池全称和在池主体、债券数量，序号跨页连续，可跨页勾选要清空的投资池。
  • 证券和主体都可以勾选「允许联动与互斥调整」，默认勾选。取消勾选时，校验结果只保留手工项。
  • 已生成批次（存在 impId）后参数锁定，需先清空再改类型或方向。

模板与上传

  • 证券模板仅四列：父池名称、子池名称、证券名称、证券代码。证券代码匹配忽略大小写，校验后使用主档中的代码。证券导入的父池名称、子池名称均必填。导入根级叶子池时，两列都填该池的实际名称，例如「CRMW库 / CRMW库」。担保人/权益人改为上传后在「导入明细」页面选择，不在 Excel 填写；旧六列模板中的主体全称和代码不再参与选择。
  • 证券模板保留 5 条完整 Demo 调入示例：24基建担保（DBB001.IB）、24地产担保（DBB002.IB）、25城投担保（DBB003.IB）、24资ABS02（108008902.IB）、25资管ABS（ABN001.IB），均调入信用债大库(new)的一级库，匹配 Demo 中默认第一条关联主体的内评 1。业务修改主体选择后，仍按实际库数据与目标池重新校验。
  • 主体模板列：父池名称、子池名称、统一社会信用代码、主体全称、主体代码。
  • 主体匹配按优先级分阶段批量查询，每批最多 500 个不同条件；高优先级未命中才查下一级，歧义仍报错。校验时统一读取主体资料、池配置、在池及在途状态、容量和所需外评，再逐行执行原规则。清空目标池批量读取各池当前在池成员，主体使用同一套取数方式。每次校验重新查询，回写后直接返回本次主体首屏和校验结果。2000 个主体首项均命中时，上传和一次校验合计读取公司简介 8 次；上传上限保持 2000 行。
  • 主体统一查询 ais_inv_ods.wind_compintroduction：先按统一社会信用代码 REGISTERNUMBER 精确查找（一对一），未填或未找到再按主体代码 COMP_ID，仍未填或未找到再按主体全称 COMP_NAME 或简称 COMP_SNAME 精确查找。唯一命中即停止，回填主体代码；信用代码异常一对多、名称重名、三项均空或全部未命中时显示行级原因。上传和重新校验均遵循此顺序，最终代码用于判重、清空差集及提交；导入明细在子池名称后展示填写的统一社会信用代码。详情和提交同样由公司简介确认主体身份，不再关联旧发行人表；清空目标池成员直接读取状态表中的名称。
  • 模板统一楷体 11 磅、浅蓝加粗表头、行高 20 磅、列宽 18；代码使用文本格式，保留示例内容。
  • 模板下载 templateCode：security_pool_import / company_pool_import。
  • 上传 multipart：request JSON Blob + file + originalFileNameListJson（单元素原始文件名 JSON 数组，用于兼容公司环境中文文件名），与调库附件提交方式一致；xls/xlsx，不超过 5MB。
  • 再次选择文件会覆盖当前未提交批次；上传后生成 impId（形如 IMP202608071347400001）。

校验与提交

强担保豁免开关：统一使用 common/constants/BusinessSwitches.java 中的代码常量 BusinessSwitches.STRONG_GUARANTEE_ENABLED，当前为 false。改为 true 可恢复豁免，修改后需重新编译并重启服务生效。关闭时，非 ABS 担保人内评 1 档也执行重点观察名单限制；开启时恢复原有重点观察名单准入及池间 in_restrict 豁免。普通担保债评级矩阵不变，ABS、禁止池及其他限制池不享受该豁免。 证券导入继续把原业务失败作为可提交提示，关闭开关不改变该策略。

证券和主体导入均保留单笔调库校验返回的流程候选，并默认推荐目标池已配置的批量调入或调出流程。批量流程留空或选「不需要审批」时，沿用单笔校验结果。单笔未返回候选时，列表只显示已配置的批量流程。

POST /api/v1/securityPoolExcelImport/queryItemPage · editRatingCompany · checkImport · queryTask · submitImport · cancelImport

导入明细与调库校验

  • 明细分页 queryItemPage：可按证券代码或主体代码的前缀、校验结果（待校验 / 通过 / 失败）筛选。
  • 仅 ABS 上传行初始化首个权益人，已确认或在途主体优先回显。仅 ABS 展示权益人和自选权益人。仅担保债展示担保人和担保人主体内评分。上传时为担保债行优先回显已保存且仍有效的担保人，否则默认选中首项。评分随选择更新。ABS 担保债的担保人选择独立保存，与权益人及自选权益人一起回显。分页与校验保留手动选择或清除，不重新覆盖为默认值。
  • 仅 ABS 展示「自选权益人」，按代码或名称搜索全市场有效主体，无需与当前证券关联。关联权益人和自选权益人分别保存，自选优先用于评级；清除自选后恢复关联主体内评。ABS 至少选一种；担保债有候选时须选择，无关联候选且单券规则不要求时可留空。自选权益人弹窗采用带标签的主体编码/名称查询区；点击行或单选框选择主体，选中行高亮，最新内评以标签展示；底部显示已选主体全称和编码。确认前仅暂存选择，取消保留原值。主体编码、主体全称和内评列按弹窗可用宽度自适应分配。
  • 各导入行独立保存担保人/权益人和 ABS 自选权益人。同一证券导入不同池时仅上传默认值相同，修改或清除某行不影响其他行，分页和刷新后保留各行选择。修改调用 editRatingCompany，以 impId + itemId 定位当前行，并清空本批旧行级校验、调库展开结果及流程选择，须重新校验；已提交批次不可修改。主体修改后须重新校验，禁止旧校验结果绕过重新校验提交。
  • 证券导入行和清空出库证券分别批量读取资料，再逐行执行规则。独立翻页集中读取当页证券和评级主体。校验首屏使用本次已回写的明细和候选，仅补查当前页尚未读取的数据。主体复用 ForbiddenPoolAdjustService.checkCompanyAdjust。ABS 的关联选择写入 rightsHolderCode，自选写入 selfSelectedRightsHolderCode；非 ABS 写入 guarantorCode。主体代码和标准名称由后端复核，提交读取本批已通过校验的持久化选择并再次校验候选资格；校验结果展示最终用于评级的主体全称和代码。ABS 最终采用的权益人（自选优先）无内评时，调入信用债分级库的校验提示“所选权益人无内评分”，与单券调整一致。
  • 勾选联动互斥时保留 linkage / mutex / related 展开项；不勾选仅手工项。
  • 点击「确认清空」时会再次提示所选池数量和出库影响，确认后才提交。取消或关闭提示会保留当前勾选。清空目标池按每个主体和债券的单笔出库规则校验，并执行联动调整。全部通过后统一走「无需审核审批流程」，立即生效并记录完整流程步骤。可在调库详情的「当前流程状态」查看。存在在途、锁定或未满足调出研究报告要求等失败时，显示具体原因，本次清空不生效。
  • 导入校验结果的手工主项显示「Excel导入」。独立清空的主项日志记录「清空目标池」。
  • 某证券导入行主券或任一同券关联项失败时，整个调库组均不可提交，保留失败代码和具体原因，不影响其他独立校验通过行；提交复用已有校验结果的关联代码集合，不重新查询同券关系。
  • item_tag 生命周期：校验态清空主项 itemTag=clear（ItemType.CLEAR）；提交时因调库服务不识别 clear，清空项 item_tag 改写为 manual，靠 adjust_type=清空目标池 区分渠道。

提交、流程与权限

  • 提交弹出「选择调库流程」；弹窗结构、卡片层级、间距与底部操作区完全对齐证券池调整页，候选规则仍按 Excel 导入规则处理。
  • 校验结果每 200 行回写一次，随后保存批次摘要。提交成功后只更新本批实际提交的 Excel 手工主项对应明细。
  • 证券每次提交从数据库集中读取评级主体候选。清空出库同样按本次批量查询确定默认主体，编辑单行时重新读取该行候选。各导入行仍采用本行已保存的主体选择。
  • 提交成功返回时，「调库校验结果」回显手工项和清空项本次实际选定的流程。
  • 证券流程策略：完整执行原单笔校验，包含产品库快速资格及信用债简易资格；Excel 专用入口将原业务未通过项统一设为可提交，保留原因并继续生成流程候选。带有产品库材料豁免资格的主项在提交时复核主券和关联市场代码的有效来源。通过公共方法 BatchAdjustFlowOptionHelper.appendConfiguredBatchFlow 追加目标池配置的 batchIn/batchOut 并设为唯一推荐。未配置 ID/Key 时保留单笔推荐。同定义的快速与批量选项按类型分别保留。
  • 流程中、调入时已在目标池均为校验不通过。 导入继续保留评级等可放行规则的原因，在“调整说明”显示“调整提示（共 N 项）”，可提交状态及原原因保存在导入快照中。全部可调整但存在调整提示时，弹窗显示“全部可调整，其中 N 条存在调整提示”。证券、主体或目标池无法识别、缺少导入权限等错误仍不可提交。
  • 提交与落池一致：证券导入不会在提交或审批结束时再被原业务失败及报告必填要求阻断，实际仍按所选流程审批。重复调入先结束旧有效状态再写入，调出已不在库的证券按已完成处理；数据对象、来源明细、关联组完整性和数据库写入异常仍检查，异常整批回滚。
  • 材料按资格豁免：满足快速资格时，本次信评报告及其他附件免提交，与选择快速、一般、特殊或批量流程无关；行级 materialExemptionType 随提交透传，同组配套项跟随主项。切换流程不改变豁免和提示，所选审批流程仍照常执行。不展示合同投资范围确认提示。证券池批量、存量批量和 Excel 共用追加方法；单笔入口保持原候选。
  • 证券按来源导入行 sourceItemId 分组，通过 BatchSecurityAdjustSubmitService 提交。直通项批量写入日志、步骤、证券快照及池状态，ABS 按原顺序处理身份及同步提醒。非 ABS 同码不同池可独立选择；同一 ABS 跨行主体必须一致；本行主项及联动、互斥、关联项使用该行保存的选择和流程，并分别保存本笔证券快照。主体导入和清空通过 BatchCompanyAdjustSubmitService 批量提交，实时读取主体、池和流程配置，批量写入调库日志、初始步骤及直通池状态。待审批项在审批通过后更新池状态。导入生效的当前在池记录受定时调库保护。人工调出或清空后保护结束，仍符合条件的成员可由任务补回。
  • 仅 audit_status=20 落地 ip_pool_status；目标池须 excel_importable；管理员 userId=1 放行。
  • 导入批次号仅管理员可见；impId 仍用于后续校验 / 提交。

关键规则与当前实现说明

  • 页面不选择目标池：父池 / 子池名称必须能解析到启用叶子池，否则该行校验失败。
  • 调整类型：Excel 手工主项 Excel导入，清空项 清空目标池；联动/互斥/关联与单笔一致。字典 DICT_ADJUST_TYPE 已登记。
  • 同一目标池有调入主项随本次提交时，才提交该池的清空项及配套项。清空先提交，导入随后提交，各项按所选流程生效。清空校验用 item_tag=clear，提交改写为 manual 并以调整类型区分。
  • 证券和主体分别使用 checkExcelAdjust 和 checkCompanyExcelAdjust 执行单笔业务规则并生成提示；证券 Excel 模板仅四列，仅 ABS 默认首个权益人并可改用全市场自选权益人。改选择后须重新校验。联动、互斥与关联项展示来源主券选择；清空目标池时，只有无已确认或占用主体的 ABS 取首个关联权益人。证券和主体导入的流程候选均保留单笔匹配，并追加及推荐已配置的批量流程。证券池批量调整和存量证券批量调整见 证券池批量调整（共用追加方法）。
  • 仅 audit_status=20 落地 ip_pool_status；驳回 / 撤回只改日志与步骤。
  • 主体 Excel 调入、调出及同批联动生效后，旗下普通债由定时任务按主体决定补入或撤销跟随记录。跳过评级、到期天数等常规条件，池关系和在途校验继续生效。ABS 由独立任务处理，债券独立取得的入池依据继续有效。
  • 主体 Excel 联动调入黑名单质押库时，可调整的联动项与证券导入一样，在「调整说明」显示「调整提示（共 N 项）」和编号列表，例如「本次调入重点观察名单23」。已校验的批次点击「重新校验」可更新提示。
  • 主体 Excel 调出勾选允许联动时，按配置展开调出联动池。已在黑名单质押库的主体生成该池的联动调出项，跳过该池的出库三条件，保留在途校验。
  • 导入批次号仅管理员可见；目标池须具备 excel_importable，管理员放行。
  • 校验分层（check 全量 / submit 不重跑 / recheck 子集）与单券一致，见 证券池调库。

ABS 主体一致性

ABS 在所有有效在库和在途申请中只允许一个主体代码；人工申请审核通过或直通成功入库后永久固定主体代码，全部出清也不更换；主体联动自动入池只生成 audit_status=00 的待确认调库日志，暂不写入 ip_pool_status 和主档五字段，也不形成永久绑定；研究员确认主体后才转为 audit_status=20 并正式入池，成功确认后才固定身份。审核通过才保存主档五字段。任意池主体联动和退出提醒共用同一规则，见ABS 跨池唯一主体与主体联动。

已查询数据复用

候选查询同时返回主体代码、名称、内评、认可机构最新外评及机构，最新外评按评级日期 ann_dt 选取。选择后随校验、提交传递，后端直接取值；单券已加载的证券信息用于校验、提交和快照，财报保存后返回本次记录，不再逐期回查。在库、在途及同一 ABS 主体一致性仍按业务时点检查。

CRMW 进入普通池的方式

CRMW 凭证可在证券池调整、批量调整和证券池 Excel 导入中按单券办理。存量证券批量调整也支持凭证，目标限定在债券产品库。前三个入口开放 CRMW 池作为目标池，沿用原调库校验。单券审批通过后写入 ip_pool_status。凭证与标的组合继续走专用 CRMW 调库，状态写入 ip_pool_status_crmw。 清空目标池包含普通状态表中的在池单券，按单券出库规则执行。
