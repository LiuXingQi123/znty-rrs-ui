证券池 Excel 导入

按证券 / 主体模板上传名单，解析父池与子池后暂存批次，校验通过再选择调库流程提交。页面不选手动目标池，池名由 Excel 解析；提交后写 ip_adjust_log，仅 audit_status=20 落池。

业务流程总览

前端 pages/security_pool_excel_import.html：上方导入参数与上传，下方「导入明细 / 调库校验结果」双 Tab。API 前缀 /api/v1/securityPoolExcelImport。

1. 导入参数选证券/主体、调入/调出；可选清空目标池、联动互斥、原因与意见。
2. 下载并上传按类型下载模板后拖入 xls/xlsx；解析父池/子池名称写入临时表。
3. 导入明细选择担保人/权益人，ABS 可自选权益人；查看内评后校验。
4. 调库校验证券走单券 checkAdjust，主体走 checkCompanyAdjust；展示可调整项。
5. 选流程提交弹窗与批量调库一致；确认后写申请/步骤，仅 20 落池。

导入参数与上传

方向与选项作用于整批；目标池不在页面选择，由 Excel 父池名称 + 子池名称解析。

POST /api/v1/commonFile/downloadTemplate · /api/v1/securityPoolExcelImport/uploadExcel

导入类型与选项

  • 导入类型：security 证券 / company 主体；调整方向：in 调入 / out 调出。
  • 调整原因、调整意见均为选填，整批共享，写入临时主表 fld002 / fld003。
  • 「首先清空目标池」仅调入可见：对本批涉及的每个目标池，将「在池但不在本批名单」的成员按单券调出 checkAdjust 生成清空项（非调用 Batch 编排服务）。
  • 「允许联动与互斥调整」默认勾选；不勾选则校验结果只保留手工项（证券导入）。
  • 已生成批次（存在 impId）后参数锁定，需先清空再改类型或方向。

模板与上传

  • 证券模板仅四列：父池名称、子池名称、证券名称、证券代码。担保人/权益人改为上传后在「导入明细」页面选择，不在 Excel 填写；旧六列模板中的主体名称和代码不再参与选择。
  • 证券模板保留 5 条完整 Demo 调入示例：24基建担保（DBB001.IB）、24地产担保（DBB002.IB）、25城投担保（DBB003.IB）、24资ABS02（108008902.IB）、25资管ABS（ABN001.IB），均调入信用债大库(new)的一级库，匹配 Demo 中默认第一条关联主体的内评 1。业务修改主体选择后，仍按实际库数据与目标池重新校验。
  • 主体模板列：父池名称、子池名称、主体名称、主体代码。
  • 模板下载 templateCode：security_pool_import / company_pool_import。
  • 上传 multipart：request JSON Blob + file + originalFileNameListJson（单元素原始文件名 JSON 数组，用于兼容公司环境中文文件名），与调库附件提交方式一致；xls/xlsx，不超过 5MB。
  • 再次选择文件会覆盖当前未提交批次；上传后生成 impId（形如 IMP202608071347400001）。

校验与提交

先校验导入行，再复用单券 / 主体调库校验；流程策略与当前批量页不同（Excel 仍注入 batch 推荐）。

POST /api/v1/securityPoolExcelImport/queryItemPage · editRatingCompany · checkImport · queryTask · submitImport · cancelImport

导入明细与调库校验

  • 明细分页 queryItemPage：可按代码关键字、校验结果（待校验 / 通过 / 失败）筛选。
  • 「担保人/权益人」下拉与批量调整可选证券一致，显示关联主体名称、关系类型和最新内评，上传时默认第一条。分页与校验保留手动选择或清除，不重新覆盖为默认值。
  • 仅 ABS 展示「自选权益人」，按代码或名称搜索全市场有效主体，无需与当前证券关联。关联权益人和自选权益人分别保存，自选优先用于评级；清除自选后恢复关联主体内评。ABS 至少选一种；非 ABS 有关联候选时须选择，无关联候选且单券规则不要求时可留空。自选权益人弹窗采用带标签的主体编码/名称查询区；点击行或单选框选择主体，选中行高亮，最新内评以标签展示；底部显示已选主体名称和编码。确认前仅暂存选择，取消保留原值。主体编码、主体名称和内评列按弹窗可用宽度自适应分配。
  • 各导入行独立保存担保人/权益人和 ABS 自选权益人。同一证券导入不同池时仅上传默认值相同，修改或清除某行不影响其他行，分页和刷新后保留各行选择。修改调用 editRatingCompany，以 impId + itemId 定位当前行，并清空本批旧行级校验、调库展开结果及流程选择，须重新校验；已提交批次不可修改。修改、校验、提交与取消串行处理，禁止旧校验结果绕过重新校验提交。
  • 证券每行复用 SecurityPoolAdjustService.checkAdjust，主体每行复用 ForbiddenPoolAdjustService.checkCompanyAdjust。ABS 的关联选择写入 rightsHolderCode，自选写入 selfSelectedRightsHolderCode；非 ABS 写入 guarantorCode。主体代码和标准名称由后端复核，提交读取本批已通过校验的持久化选择并再次校验候选资格；校验结果展示最终用于评级的主体名称和代码。
  • 勾选联动互斥时保留 linkage / mutex / related 展开项；不勾选仅手工项。
  • 首先清空目标池：差集成员走单券调出校验；本批编码若已有在途流程则该导入行失败；非本批编码在途不纳入清空。
  • 校验结果列调整类型：手工主项「Excel导入」，清空项「Excel清空」。
  • 某证券导入行手工主项校验失败时，该行的联动、互斥和关联项不单独提交，不影响其他校验通过行的提交。
  • item_tag 生命周期：校验态清空主项 itemTag=clear（ItemType.CLEAR）；提交时因调库服务不识别 clear，清空项 item_tag 改写为 manual，靠 adjust_type=Excel清空 区分渠道。

提交、流程与权限

  • 提交弹出「选择调库流程」；弹窗结构、卡片层级、间距与底部操作区完全对齐证券池调整页，候选规则仍按 Excel 导入规则处理。
  • Excel 流程策略（当前代码）：先拷贝单券/主体 flowOptions，再 injectBatchFlowOption 把目标池 batchIn/batchOut 插到候选最前并 recommended=true，可能压过单券 special/简易推荐。
  • 与批量/存量对比：证券池批量、存量批量已不注入、不回填 batch 流程，完全透传单券候选。Excel 仍注入属有意差异（非「与批量一致」）。
  • 证券按来源导入行 sourceItemId 分组，通过 addExcelImportAdjustLogList 复用单券提交步骤。同码不同池可选不同主体；本行主项及联动、互斥、关联项使用该行保存的选择和流程，并分别保存本笔证券快照。整批先检查已有在途流程，再逐行创建流程，避免同批新流程阻断其他行。主体仍按主体分组 addCompanyAdjustLog；清空出库先于导入提交。
  • 仅 audit_status=20 落地 ip_pool_status；目标池须 excel_importable；管理员 userId=1 放行。
  • 导入批次号仅管理员可见；impId 仍用于后续校验 / 提交。

关键规则与当前实现说明

  • 页面不选择目标池：父池 / 子池名称必须能解析到启用叶子池，否则该行校验失败。
  • 调整类型：Excel 手工主项 Excel导入，清空项 Excel清空；联动/互斥/关联与单笔一致。字典 DICT_ADJUST_TYPE 已登记。
  • 首先清空目标池仅调入：清空主项及同一来源的联动、互斥和关联项一同提交出库，先清空出库，再导入；清空校验用 item_tag=clear，提交改写 manual + adjustType 区分。
  • 证券校验复用单券 checkAdjust，主体校验复用 checkCompanyAdjust；证券 Excel 模板仅四列，页面默认首个关联主体并允许修改，ABS 支持全市场自选权益人且自选优先。改选择后须重新校验。联动、互斥与关联项展示来源主券选择；首先清空目标池自动生成的出库成员沿用原有默认主体逻辑。流程候选：Excel 仍注入 batchIn/Out 推荐；批量/存量见 证券池批量调整（已不注入）。
  • 仅 audit_status=20 落地 ip_pool_status；驳回 / 撤回只改日志与步骤。
  • 导入批次号仅管理员可见；目标池须具备 excel_importable，管理员放行。
  • 校验分层（check 全量 / submit 不重跑 / recheck 子集）与单券一致，见 证券池调库。
