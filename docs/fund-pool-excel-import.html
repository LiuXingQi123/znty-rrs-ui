业务流程总览

上传七列基金模板，由服务解析目标池、校验原始行、扩展关联调整并选择一般流程提交；支持导入前清空目标池。

1. 设置导入参数选择调入调出、关联调整、清空目标池和共用原因建议。
2. 下载并上传模板填写七列模板，上传 xls/xlsx，保留原始单元格和行号。
3. 校验导入任务校验原始行、池权限、基金规则和跨行冲突，生成清空差额。
4. 确认一般流程查看整组结果，为通过项选择服务允许的一般流程。
5. 提交审批申请先提交清空组再提交导入组；最终审批通过后才改变池状态。

导入参数与上传

模板结构、上传参数及服务端原始行存储与债券导入文档采用相同说明层次。

POST /api/v1/fundPoolExcelImport/uploadExcel

导入类型与选项

  • 支持调入 / 调出；可选择是否包含联动互斥项，“清空目标池”只允许调入时勾选。
  • 调整原因和建议各最多1000字；启用清空需另填清空出池共用的基金评分、投资类型和领导审批三项。
  • 上传后方向、选项和清空资料锁定；导入行只读。需要改变参数时重置任务并重新上传。
  • 模板下载 POST /api/v1/commonFile/downloadTemplate，templateCode=fund_pool_import。

模板与上传

  • 七列依次为父投资池、子投资池、基金名称、基金代码、基金评分、基金投资类型、分管领导审批；第二页为填写说明及下拉提示。
  • 只解析首个工作表，支持 .xls / .xlsx，文件不超过5MB、非空数据不超过2000行，保留真实 Excel 行号。
  • 父子池须直接对应启用基金叶子池；匹配多个目标池时明确失败，不自动选择。基金代码及名称按权威主档校验。
  • 非法原值仍保留；数值单元格使用真实值，不按显示格式四舍五入后通过评分精度校验。

校验与提交

服务端任务与校验快照是提交依据，客户端仅回传一般流程选择。

POST /api/v1/fundPoolExcelImport/queryItemPage · checkImport · queryTask · submitImport · cancelImport

导入明细与调库校验

  • 复用 FundPoolAdjustService.checkExcelImportAdjust 的基金通用规则，并同时校验 excel_importable 与 adjustable 池权限。
  • 三项基金调库字段逐行校验；单个源行的手工项与关联项整组通过或失败，未勾关联选项时仅保留主项。
  • 不同源行涉及同基金、同池即产生跨源冲突，方向相反也失败；所有相关组标记失败，不静默合并。冲突提示最多列5个来源并显示总数。
  • 页面摘要 chk_dscr 最多500字，完整原因保存在服务快照；本页无报告上传，手工项需要报告时在校验阶段失败。

提交、流程与权限

  • 申请标记“Excel导入 / Excel清空”，主项使用目标池对应的一般流程，关联项沿用主项流程，不注入快速或批量流程。
  • 提交依据服务端保存的任务、原始行和校验结果；客户端选择 selectedFlowId 及其关联键、类型，共用原因建议允许在提交时更新。
  • 每个源行独立 FUND 申请批次；先清空组后导入组，所有申请先复核再创建流程。
  • 允许只提交通过组或仅提交清空组；提交过程中任一失败整体事务回滚。任务加锁，已提交任务不能重复校验、取消或提交。

清空目标池与任务存储

清空由有效池状态与模板保留集合求差额，产生出池申请，不直接删除池成员。

清空差额与保留集合

  • 保留集合使用全部“已解析到目标池且代码非空”的原始行；即使三项调库字段无效，仍保留对应代码，避免误清。
  • 对 audit_status=20、未删除的目标池成员求差，跳过目标池已有在途申请的基金。
  • 每个清空组使用共用三项资料并执行完整出池校验；清空出池不会立即释放容量，导入仍按实际有效成员数校验。

任务主从表与字段

  • sys_imp_tmp.biz_type=fund_pool_excel，保存模板、方向、选项、共用文本和完整校验、提交结果。
  • 主表 fld001 存方向，fld011 / fld012 存原因建议，option_json 存锁定选项，result_json 存完整快照。
  • 明细 fld001～fld007 存基金代码、权威名称、父池、子池、原始评分、类型和领导审批值；fld009 / fld010 存解析池ID、类型。
  • sourceItemId 标识源行分组；无效原值保留，提交禁止以客户端拼装数据覆盖服务快照。

关键规则与当前实现说明

  • 基金导入与证券导入共用任务主从表，通过 biz_type 隔离；申请仍只写基金日志和步骤表。
  • 管理员1的导入权限口径与证券导入保持一致；服务仍复核池状态和基金业务规则。
  • 提交仅创建00申请；清空和导入均须基金最终审批通过后才改变池状态。
  • 任务取消与审批终止是不同操作：已提交任务不能以取消导入方式撤销审批申请。
  • 三字段精度、枚举和基金通用规则见 基金池调整申请。
模板保留集合、跨源冲突和提交快照均由服务计算，防止无效行引起误清或客户端绕过校验。
