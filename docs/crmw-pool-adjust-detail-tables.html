CRMW池调库详情

查看 CRMW 调库申请，或在调整模式下关联 CRMW 凭证与标的证券并提交首次申请。具体主体的结果字段展示为“主体内评分”；准入矩阵的分类字典及档位比较仍称“内评分档”，评分取值和档位编码保持不变。

标的债券一券多码调库

CRMW 凭证自身只有一个代码。本功能只按标的债券的 Wind 非空 ISIN 查询同券代码，排除自身、去重、不递归；空 ISIN 和临时代码不关联。

校验在手工、联动、互斥项后追加 itemTag=related 关联调整项。每个代码按自身市场、凭证与标的组合在池状态、活动池组、冻结期及原规则独立校验，同池调入累计容量。主项失败阻断关联项；关联项失败单独展示，仅提交通过项，与证券池一致。

关联项沿用原凭证、主项分组、流程和批次，仅手工项创建步骤，报告要求由同组手工项承担。提交 items[] 携带实际 securityCode/securityShortName/securityType，日志、快照和池状态均保留实际标的代码；直通即时生效，人工审批最终通过后同批生效。出池按原凭证、实际标的及目标池精确处理，保留其他凭证的组合。

批量及 Excel 导入复用相同逻辑，同批多个同券主行展开的重复组合按凭证、标的、目标池、方向去重，显式手工项优先；Excel 关联项全称、市场和类型按自身主档展示。活动流程通过同批任一组合定位，关联码审批中不能重复申请同池组。

queryCrmwAdjustLogList 展示当前组合全部历史及同批关联项，不按请求批次或终态过滤，返回项增加实际标的代码和名称；校验表及审核、详情记录表展示这些字段。自动到期调出继续按实际在池组合逐条处理。本次不变更表结构或迁移历史数据。

流程总览业务逻辑涉及表规则说明文档目录

标的证券主档差异提示：证券基本信息区复用公共差异模块，独立调用 POST /api/v1/securityPoolAdjust/querySecurityMasterDetail（{ securityCode: 标的证券代码 } → SecurityInfoDetailDto）。差异标签以橙色突出，悬停或键盘聚焦显示页面值、主档值和本次读取时间；空值提示“（空）”，日期、数字按业务值比较。申请/详情调整模式的担保人及内评按原选择控件比较，详情只读模式与审核按原快照显示值比较；ABS 权益人名称和市场关联不比较。

原快照、编辑权限、校验和提交保持不变，比较结果不进入提交参数。CRMW 凭证基本信息本身直接读取主档，不重复查询对比；对比只使用标的证券代码，不发送凭证代码或申请 ID。失败显示对比不可用，不影响原操作。将 js/security_master_diff.js 的 window.RrsSecurityMasterDiff.enabled 定义改为 false 并刷新页面即可统一关闭；打印/PDF 保持原样。主档值为本次读取结果，不代表上游已实时同步。

正式证券市场直接读取 rrs_securityinfo.market（VARCHAR(10)，表末尾新增，与 Wind EXCHMARKET 原值一致，银行间使用 NIB）；临时代码使用登记市场。同券其他代码按 Wind 非空 S_INFO_ISINCODE 查询，空 ISIN 不关联。详情的 marketCode 和 relatedMarketCodes 为只读，同市场多个代码完整展示，不再提交旧市场字段。每条市场代码独立校验；证券与 CRMW 快照不再保存市场列，历史详情补查当前关联关系，其余业务字段按原快照回显。主档 sec_id 是独立外部证券 ID，转正保留正式证券 ID。

业务流程总览

从页面操作到数据库读写的主要路径。

POST /api/v1/crmwPoolAdjust/queryCrmwDetailPOST /api/v1/crmwPoolAdjust/queryCrmwPoolStatusPOST /api/v1/crmwPoolAdjust/queryCrmwAdjustPoolListPOST /api/v1/crmwPoolAdjust/queryCrmwAdjustLogListPOST /api/v1/crmwPoolAdjust/queryCrmwAdjustStepListPOST /api/v1/crmwPoolAdjust/checkCrmwAdjustPOST /api/v1/crmwPoolAdjust/addCrmwAdjustLogWithFiles
1. 识别模式

view 只读；adjust 首次提交。详情键 = 凭证 crmwScode + 标的 securityCode（缺一不可）。

2. 并行加载

按双码读凭证/标的详情、当前组合在池、可调池、日志和步骤。

3. 选择方向

仅叶子池可选，当前在池决定可调入或可调出范围；可调入库默认仅展开「信用债大库(new)」，其他根节点默认收起（CRMW 池树不含该节点时即默认全部收起），可调出库默认全部展开。

4. 后端校验

checkCrmwAdjust：pending/容量/来源/限制/互斥/开放日等；行业已注释；无内评矩阵；标的债仅到期等。

5. 首次提交

写申请、附件及必要步骤；详情页不处理后续审批动作。

查询、校验与操作逻辑

按当前前后端实现归纳主要触发场景。

查看模式

调库记录固定按 securityCode + crmwScode + crmwStype 且 pool_type=crmw 查询当前“标的证券 + CRMW 凭证”组合的全部历史，不按批次或状态过滤，按提交时间倒序展示调整原因和提交时间；URL 带 adjustBatchNo 时，同批记录以浅蓝底色高亮；批次仅用于流程步骤与申请快照定位。附件按全部日志 ID 去重后一次批量查询，并按返回的 mainId 回填；标的证券基本信息共 29 项且顺序与证券池调库页一致，「剩余期限(天)」隐藏保留，新增只读「证券期限」展示 date_exists_str，在展望评级后只读展示担保人；不触发 check 或写表。

证券基本信息中的“证券分析”随内容自动增高，最少 3 行、最多 20 行；超过 20 行时在框内滚动，最大输入长度为 5000 字。

调库记录表格列顺序为：序号、CRMW凭证、投资池名称、调整类型、调整方向、调整原因、信评报告、其他材料、提交时间、审批流程、审核状态。

发行主体财务数据

证券基本信息下方调用 queryIssuerFinancialList，直接只读展示返回的四期。按中国标准时间的当前自然年确定四期：默认前三列为前三年年报，第四列为数据库最新一期；最新一期恰好为上一年年报，或主体完全没有财报时，显示前四年年报。缺失期保留报告日期，指标为空，不以季报或其他年份替代。城投债/产业债按钮仅切换指标口径，不提供报告期编辑或保存，不参与审批提交。

导出 PDF

底部操作栏「导出 PDF」调用公共 js/print_export.js，打印证券基本信息、财务数据、CRMW 基本信息、当前所在池、调库记录、原因和建议；页面展示「当前流程状态」时，同时导出流程名称和完整步骤表（步骤名称、步骤结果、开始时间、处理人、处理结果、处理时间、处理意见），包含暂无流程步骤的空状态。导出前自动展开流程状态区，打印结束或取消后恢复原折叠状态；页面未展示该区块时不导出。样式在 css/common.css。

调整模式

可调池仅 pool_type=crmw（in/out 同集合，无内评矩阵）；按组合当前在池过滤。担保人候选沿用证券池调库的类型及排序口径，页面默认选中第一条，用户可改选，变更后联动 AIS 最新主体内评分；选池/方向后携带 guarantorCode 调用 checkCrmwAdjust。

校验返回

手工+联动/互斥/关联；failReasons/warnings 分列；失败分条编号；同组底色。仅通过手工项可选流程。

首次提交

请求携带 crmwScode/crmwStype 与 securityCode（无 mktcode）；直通 recheck 子集后只改 ip_pool_status_crmw；可写 ip_adjust_security_snapshot_crmw。

职责边界

审批走「CRMW池调库审核」。view 入口常带组合键 + adjustLogId；process 进审核页。

附件处理

无附件走 JSON 提交，有附件走 multipart；请求通过与 files 同序的 originalFileNameListJson 保留中文原始文件名，sys_attachment 通过 adjustLogId 关联申请。

关键规则与边界

帮助区分当前状态、历史记录和流程实例。

ABS 详情

CRMW 详情与审核页展示普通权益人、自选权益人和实际生效主体内评；非 ABS 仍展示担保人。

模式边界

view 模式始终只读；adjust 模式仅负责首次申请。

当前状态口径

当前池必须读取最终状态表，申请日志只代表过程和历史。

重复提交

存在待处理（pending）步骤或目标池状态已变化时，后端重新校验并阻止过期提交。

文档口径来自当前页面、Controller、Service、Mapper XML 与对应 requirements；后续代码调整时应同步维护本页。

业务入口与处理范围

本页所属业务为 bond。附件列表由页面明确发送 businessDomain=bond 和 adjustLogIds，附件下载只发送 id；公共 apiPost 原样发送参数。我的事宜仅在新页面 mounted 时读取业务入口；本页直接读取详情、批次记录、步骤和附件，后端业务查询及审批不校验入口名单。普通用户仅处理本人待办，不能处理他人或无处理人的步骤；后端 AdminUserIdUtil 统一识别管理员（ID 为 1 或整数 10000～10100），管理员可接管待办并优先处理本人步骤。审核页使用相同 ID 规则展示操作：优先定位本人待办，无本人待办时管理员展示首个待办，其他人不启用审批操作；实际提交根据真实步骤校验处理资格。各业务审批状态、会签及驳回修改逻辑保留；投资池权限独立。工作台事项页签键带业务代码，返回我的事宜只刷新数据，不重新读取入口。业务入口说明
