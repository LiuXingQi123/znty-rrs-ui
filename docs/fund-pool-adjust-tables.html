基金池调整申请

基金研究 · 独立申请链路 · 本期不含审核与落池

功能边界

页面按照“基金列表 → 基金详情与选池 → 校验确认 → 选择调库流程 → 提交申请”运行。第一步展示基金基础信息、当前所在池和调库操作（可调入库 / 可调出库）；点击下一步完成校验后进入第二步，保留基金基础信息和当前所在池，隐藏调库操作，展示调库校验结果、原因和建议。基金页面、样式、Controller、Service、Mapper、XML 和业务对象均为独立文件，不调用证券池调整业务模块。

提交后写入 ip_adjust_log_fund 与 ip_adjust_step_fund，状态为 00。最终审批通过时更新 ip_pool_status_fund，基金审核/详情及我的事宜已接入独立 fund 业务；调整历史由独立的基金池调整历史页面查询。

数据表

表用途
rrs_fundinfo基金主数据与只读基础信息，不建立调库快照。
ip_adjust_log_fund基金手工、联动和互斥调库日志；批次号使用 FUND 前缀。
ip_adjust_step_fund基金一般流程的开始、发起和待审批节点。
ip_pool_status_fund基金当前池状态；本期只读，不由申请接口写入。
sys_attachment基金报告和其他材料，关联表名为 ip_adjust_log_fund。

页面字段

  • 列表：基金代码、简称、全称、产品类型、最新净值、成立日期、基金经理、基金管理人、最新规模、数据日期；基金代码和基金简称均可使用相同链接样式进入对应基金的调库申请步骤。
  • 只读详情：基金简称、代码、产品类型、最新净值、成立日期、基金经理、基金管理人、基金托管人、累计净值、投资风格、交易价格、发行规模；标题处展示当前调整人和记录更新时间。
  • 最新净值以品牌色重点展示；可调入、可调出投资池树默认折叠。
  • 确认页：基金评分必填数字；基金投资类型必填五选一；风管领导审批必填，使用 el-radio-group 单选“是 / 否”。
  • 确认页以与基金基础信息一致的三列边框描述表格展示基金调库信息，字段为必填；调整原因、调整建议均为非必填；导出 PDF 不包含基金调库信息和原因建议区块。
  • 投资池名称展示全路径，例如“信用债大库(new)/一级库”；一般流程候选显示使用目标池默认流程的原因说明。
  • 不展示债券近三年财务数据、发行主体、担保人、权益人或主体所在池。

接口与流程

接口说明
queryFundPage / queryFundTypeList基金列表及产品类型。
queryFundDetail / queryFundPoolStatus基金只读详情与基金当前池。
queryAdjustPoolList按用户权限、fund 品种及 SSE/SZSE/OTC/HKEX 市场过滤投资池。
checkAdjust校验通用基金规则，展开联动、互斥项，每条手工项只返回一个一般流程。
addAdjustLog / addAdjustLogWithFiles提交 JSON 或 multipart 申请，后端重读基金主数据。

校验与附件

执行权限、启停/锁池、基金品种和市场、在池状态、容量、在途、重复提交、池关系、冻结期、开放日和报告限制。不执行债券到期、主体评级矩阵、担保人、禁投主体、财务数据或基金评分范围规则。

基金临时代码管理 新增的占位主档可参与基金调库，仍执行产品类型、市场及其他既有校验。基金 O32 节点命中临时映射且状态为 temporary 时转人工待处理（pending）。人工转正式替换在途代码，已在池时办理临时调出与正式调入；取消发行会停用占位主档但不自动清理业务引用，可能阻塞后续业务。

附件分类：fund_report_hand/in/out、fund_material_hand/in/out。可调入库和可调出库均在每个目标池行内提供“相关报告 / 其他材料”的“选择报告”和“上传附件”入口。基金报告选择弹窗与证券池调整保持同构：内部/外部报告独立查询，支持报告类型快捷筛选、标题、证券编码、日期范围、分页、附件下载、跨页勾选恢复和已选清单，并按目标池分别维护。

提交按钮先校验基金评分和基金投资类型，再弹出“选择调库流程”。流程弹窗按通过校验的手工调库项逐项展示目标池全路径、方向、一般流程候选及默认流程命中原因；确认流程后才调用提交接口。调整原因和调整建议可留空。
