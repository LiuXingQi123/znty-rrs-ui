业务流程总览

维护临时基金登记与占位主档，人工选择正式基金转换，或办理取消发行、删除登记，并记录操作事件和替换明细。

1. 查询登记按临时代码、简称、状态和操作来源筛选。
2. 新增临时基金填写四项基础信息，创建临时登记与 L 状态占位主档。
3. 人工转正式选择已有正式基金，锁定主档并替换在途代码和有效在池关系。
4. 取消或删除按状态和业务引用限制办理取消发行或删除登记。
5. 保留追溯保存生命周期事件、转正明细及终态业务历史。

查询与下拉选项

登记列表展示生命周期状态；正式选项只能选系统已有有效基金。

POST /api/v1/tempFundCode/queryTempFundCodePage · queryTempFundCodeOptions · queryFormalFundOptionList

列表查询与筛选条件

  • 主表 rrs_temp_fund_code，列表允许展示软删除映射，便于检索 deleted 状态。
  • tempFundCode / tempFundShortName 模糊匹配；statusList / oprtSourceList 多选，页面默认来源为人工。
  • 按 temporary、updated、cancelled、deleted 的状态顺序，再按更新时间、创建时间、ID倒序排列；状态名称由前端字典展示。

选项与正式选基金

  • 基金品种选项直接读取有效基金大类字典，不依赖主档已有品种；市场选项用于新增临时主档。
  • 正式候选读取已有、有效、非临时基金；名称、代码、类型和市场以服务端主档为准。
  • 状态 temporary 才展示转正式、取消发行、删除操作；操作人使用当前登录 operatorId。

新增、转正式、取消与删除

操作使用独立基金临时代码服务，不安排定时自动转正。

POST /api/v1/tempFundCode/addTempFundCode · editTempFundCodeToUpdated · editTempFundCodeToCancelled · deleteTempFundCode

新增

  • 必填 tempFundCode / tempFundShortName / tempMarketCode / tempSecurityType 四项；不采集主体、担保或财务字段。
  • 校验映射和主档代码未被占用，新增登记 temporary、人工来源，并创建未删除的基金占位主档。
  • 主档全称等于简称，security_status=L；新增事件保存完整 INSERT 快照。

转正式（核心）

  • 只允许 temporary 映射；临时与正式代码必须不同，正式基金必须仍有效。按主档 ID 顺序加锁后锁映射并重新校验。
  • 映射保存正式主档资料，不覆盖正式基金主档。替换未删除且审核00/11的在途日志代码、名称和品种，保留批次、步骤、附件及调库资料。
  • 处理有效在池关系后将映射改 updated、临时主档停用为D，并写 UPDATE 事件与成功替换明细；任一失败整体回滚，不留失败技术明细。
  • 正式代码存在同池在途申请不阻止转换；后续审批落池时仍执行最终状态校验。

取消发行

  • 只允许 temporary；允许已有业务引用时取消，映射改 cancelled，临时主档改D并记录事件。
  • 已有申请、步骤和池状态保持原记录；不自动驳回、清理或恢复申请，后续处理可能因主档停用而受阻。

删除登记

  • 只允许 temporary，且不得存在任何未删除的基金日志或基金池状态引用，终态日志也计入引用检查。
  • 映射改 deleted 并软删除，记录 DELETE 事件；不删除或停用占位主档，主档仍为L。

转正时调库日志与池状态处理

在途申请改码，有效在池成员按池执行“临时出 / 正式入”，已结束业务保留原样。

在途申请替换

  • 仅处理00/11日志；保留原审核状态、流程节点、处理人、三项基金字段、原因建议和附件关联。
  • 不迁移终态历史、已提交 Excel 历史、净值历史、报告中的全局基金代码及其他业务。
  • 已有 O32 人工 pending 步骤不会因转正自动处理；新正式基金申请按正式代码规则执行。

有效在池转换分支

  • 逐池读取 audit_status=20、未删除的临时代码状态，生成临时出池审计日志并软删除该状态。
  • 正式代码尚未在同池时，创建正式入池日志和有效状态，继承原池信息，复制所需附件；不另起新的审批流程。
  • 正式代码已在同池时仅处理临时出池，不重复建立正式池状态；终态原日志保持原代码。
  • 每次成功替换写 rrs_temp_fund_code_update_log，与映射、主档、日志及状态变更同事务。

关键规则与当前实现说明

  • 本模块只提供人工生命周期操作，不提供定时自动转换；临时基金判定为有效登记且 status=temporary。
  • 临时基金 O32 节点转人工 pending；人工转正不会自动通过已有 pending 步骤。
  • 取消发行允许引用、会停用主档；删除登记禁止引用、保留主档L，两者业务后果不同。
  • sql/fund/rrs_temp_fund_code_schema.sql 初始化先 DROP 再重建登记、事件、替换明细三表，会清除原数据；不提供动态 SQL 升级入口。
  • 基金当前池与终态历史分别见 基金池查询、基金池调整历史。
转正不是全库代码替换：只迁移明确支持的在途基金申请和有效基金池关系，原历史仍可追溯。
