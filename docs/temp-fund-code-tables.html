基金临时代码管理

基金研究 · 查询临时代码 → 新增基金占位 → 人工转正式 / 取消发行 / 删除映射。查询区、列表、分页及弹窗沿用债券临时代码管理，基金页使用独立的 css/temp_fund_code.css，债券页使用 css/temp_security_code.css，两页保持相同布局与风格。

页面字段与选项

  • 查询支持临时基金代码、基金简称模糊检索，状态与操作来源多选。默认来源为人工（manual），重置恢复该默认并回到第一页。
  • 状态为 temporary 临时、updated 已更新、cancelled 已取消、deleted 已删除；只有临时状态显示更新、取消发行、删除按钮。列表保留软删除映射，可按已删除状态检索。
  • 新增四项必填：tempFundCode 临时代码、tempFundShortName 基金简称、tempMarketCode 市场、tempSecurityType 产品类型。基金全称与简称一致；不填写债券发行主体、日期或 CRMW 等字段。
  • 市场采用既有基金页面的 11 项 MarketCode：SSE、SZSE、CIBM、BSE、COMPANY、OTC、HKEX、QDII、JWCW、UNKNOWN、OTHER。实际调库仍执行投资池支持市场规则。
  • 产品类型由后端字典返回：closed_fund 封闭式基金、open_fund 开放式基金、qdii_fund QDII基金类型、lof_fund LOF基金类型、etf_fund ETF基金类型。该字段不同于基金调库的投资类型。
  • 转正式弹窗显示四项只读临时信息；正式基金按代码、简称或全称远程搜索，选择后带出代码、市场和产品类型。正式信息初始为空，不允许手工改写正式快照。

新增与人工转正式

  • 新增状态固定为 temporary，写入临时映射与基金占位主档：source_system=temporary、security_status=L、is_deleted=0。已有代码不得重复新增。
  • 正式基金必须来自已有有效主档，排除临时占位、停用和删除数据；正式代码不能与临时代码相同。本期不增加自动替换定时任务。
  • 转正式只提交 id/fundCode/operatorId，后端重新读取正式基金全称、简称、市场与产品类型，写入映射快照并记为 updated。
  • 在途日志（audit_status=00/11）只替换基金代码、全称、简称和产品类型，保留批次、流程快照、原步骤、原附件关联及三个调库参数；终态历史日志保持原码。
  • 已在池状态（audit_status=20）逐池写临时代码调出日志并软删除临时池状态；正式代码尚未在同池时再写正式调入日志并建立正式池状态。正式已在同池时只办理临时调出。
  • 新入池日志复制原基金日志附件关联，保留基金报告和原文件分类。原基金评分、投资类型、风管领导审批等业务信息按原记录继承。
  • 转正式停用临时占位主档：security_status=D，更新 updt_time；主档 is_deleted 保持 0，不额外写退市日期。
  • 正式基金同池已有在途申请时仍允许替换，冲突交给后续基金审批校验。转正中的执行异常使本次操作整体回滚。
  • 转正、基金提交和审批共同按主档 ID 顺序加锁，取得锁后重新读取业务状态；审批等待期间代码被替换时提示刷新。
  • Excel 原始行、校验快照及已提交历史保留。旧临时代码转正或取消后，未提交批次在任何日志写入前整体拒绝，提示重置重传。

取消、删除与 O32

  • 取消发行仅允许 temporary → cancelled：停用基金占位主档（security_status=D、更新 updt_time），主档 is_deleted=0。已有调库和池引用不自动移除，可能阻塞后续业务；页面二次确认会明确提示该影响。
  • 删除仅允许 temporary → deleted，且任何未删除的基金调库日志或池状态引用均会阻止删除，终态历史日志也包含在内。通过校验后只将映射 is_deleted 置为 1，保留占位主档当前状态；页面二次确认说明删除范围。
  • updated/cancelled/deleted 均不再提供更新、取消或删除操作。取消确认时不发业务请求。
  • 申请初始步骤及后续审批均按未删除登记的 status=temporary 识别有效临时基金；O32 转人工待处理（pending）。普通 auto 节点与正式基金 O32 保持现有处理方式。
  • 操作人从当前登录上下文读取 operatorId。操作来源保留 manual/job/other 字典，但本期没有基金自动替换任务。

接口

以下均为 POST，接口前缀 /api/v1/tempFundCode/。

接口后缀请求及响应
queryTempFundCodePagetempFundCode/tempFundShortName/statusList/oprtSourceList/pageIndex/pageSize；响应 records/total，包含临时四字段、正式基金快照、状态、来源和更新时间。
queryTempFundCodeOptions空对象；响应 {securityTypes:[{securityType,securityTypeName}]}。
queryFormalFundOptionListfundKeyword；响应正式基金选项，含 fundCode/fundName/fundShortName/marketCode/securityType/securityTypeName。
addTempFundCode临时四字段与 operatorId；新增映射和占位主档。
editTempFundCodeToUpdatedid/fundCode/operatorId；人工转正式。
editTempFundCodeToCancelledid/operatorId；取消发行。
deleteTempFundCodeid/operatorId；软删除临时映射。

sql/fund/rrs_temp_fund_code_schema.sql 先用 DROP TABLE IF EXISTS 删除登记审计表、替换明细日志和登记主表，再用 CREATE TABLE IF NOT EXISTS 完整重建三表。执行会清除三表原有数据；本模块不提供动态 SQL 升级入口。
