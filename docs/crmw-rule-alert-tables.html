CRMW规则提醒

业务文档总览 · 我的事宜 · 定时任务

业务角色示例：A 公司与 B 机构

  1. 标的债券：A 公司发行的债券，是接受信用保护的对象，A 公司是标的债发行人
  2. CRMW 凭证：由 B 机构创设／提供信用保护，B 机构是这里的创设方／保护方
  3. 创设方／保护方内评：B 机构最新的主体内评，不等于 A 公司的主体内评，也不等于凭证自身的证券评级

本任务检查“B 机构的 CRMW 凭证＋A 公司发行的标的债券＋当前池”这一组合。凭证代码 crmw_scode 用于查找凭证主档，其 issuer_code 对应 B 机构；标的代码 security_code 对应 A 公司发行的债券。内评和观察／重点观察名单的检查对象均为 B 机构。

1. 业务入口与规则

我的事宜 → 债券 → CRMW规则提醒。任务编码 crmw_rule_alert，每天09:13，Cron 0 13 9 * * ?，Demo默认关闭，无扩展参数。

按第十八条，每天复核有效CRMW在池组合的创设方/保护方风险。主体取凭证主档发行人，不取标的债发行人或担保人。内评取该主体在AIS评级视图中ts最新的total_score，不沿用主档或快照旧评分。

条件结果
内评3档及以上：1、2+、2、2-、3+、3不因评级触发提醒
内评低于3档：3-、4生成待办，由研究员决定是否出库
创设方已在观察或重点观察名单独立触发，研究员决定组合出库或主体进入禁止库

按启用内评档位的sort_no比较；每天按当前风险状态扫描，包含存量风险。凭证、唯一主体、最新有效内评或3档配置缺失时整轮报错回滚，不猜主体，不把无内评算作低评级。

2. 列表与人工处理

凭证代码、标的代码及提醒状态支持筛选，独立分页和角标。列表展示凭证、标的、创设方代码和名称、最新内评、当前池、原因、扫描及处理时间。仅债券业务显示，沿用共享提醒范围。

  1. 去CRMW调库：凭证和标的一起定位到CRMW申请页，研究员人工发起出库
  2. 主体禁投调整：使用创设方代码定位主体，人工选择禁止库并发起审批
  3. 标记已处理：仅保存处理人和时间，保留本次依据，不自动改池；跳转本身不改变提醒状态

3. 待办生命周期

组合键为凭证＋标的＋当前池。依据还包含入库日志、主体、最新内评及原因。待处理记录刷新；最近记录已处理且依据未变时不再重复提醒；依据变化后重新生成。恢复合规或退出扫描范围时旧待处理失效。状态：00待处理、20已处理、99已失效。

每次新增、刷新、失效、人工处理均保存完整事件快照。任务摘要区分本轮命中、沿用已处理、本轮失效及仍待处理。

4. API

提醒页面使用独立的CrmwRuleAlertController → CrmwRuleAlertService → CrmwRuleAlertMapper，只负责分页和人工处理。定时任务另由CrmwRuleAlertTaskService及Task Mapper执行；execute()包装计时、日志、失败结果及事务回滚，私有doScanCrmwRuleAlerts()执行扫描，沿用doAutoOutExpired的结构。

POST接口请求返回
/api/v1/crmwRuleAlert/queryAlertPagecrmwScode（包含匹配）、securityCode（前缀匹配）、alertStatus、pageIndex、pageSizeApiResponse<PageResult<CrmwRuleAlertDto>>
/api/v1/crmwRuleAlert/editAlertProcessedid、currentUserId、currentUserName必传更新后的提醒

5. 独立表结构

ip_crmw_rule_alert 保存当前提醒，ip_crmw_rule_alert_evt 包含主表全部字段，另有evt_id、opter_id、opt_time、oprt_type。任务操作人为0；人工操作保留处理人。无物理外键及二级索引。

6. 初始化与启用

  1. 通过脚本工具初始化新模块建表脚本 rrs_crmw_rule_alert_schema.sql，勿重置已有业务表
  2. 已有环境在定时任务管理新增任务编码crmw_rule_alert、Cron 0 13 9 * * ?，参数留空；新环境Demo已包含配置
  3. 确认凭证发行人代表实际创设方/保护方，并已维护最新评级和主体观察名单；先立即执行检查结果，再按需启用调度

Demo脚本仅清空本模块提醒及审计，不预置虚构待办。09:13晚于06:00名单同步，避开整点补债、第12分钟换码及每6分钟导出；不同任务没有全局编排，须结合实际耗时安排。

7. 大表查询

任务候选只关联CRMW池状态与投资池，去掉外层排序。主档、最新评级和名单按本轮涉及的凭证/主体去重后分别批量读取；最近提醒按组合最大有效ID批量读取，不再逐组合查库。每条读取SQL最多涉及两张表，没有相关子查询或无业务意义的排序。最新评级取最大更新时间，最新空评分不回退；页面分页顺序保持原样。无候选时跳过大表资料查询。本次不改索引或表结构，百万级数据实际耗时仍需结合真实MySQL执行计划验证。
