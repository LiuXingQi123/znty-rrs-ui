股票池批量调整

选择启用股票叶子池和候选股票，逐股票复用单笔校验，按完整分组创建独立 STOCK 批次并进入一般审批流程。

业务流程总览

前端 pages/batch_stock_pool_adjust.html：池列表 → 第一步选股与材料 → 第二步校验与提交；菜单紧接股票池调整。

1. 选择目标池查看本人可调整股票叶子池、全路径和有效成员数量。
2. 筛选股票按调入/调出方向查询候选，跨页勾选股票与共享材料。
3. 批量校验逐股票展开主项、联动和互斥，展示阻断与警告。
4. 选流程提交为通过的完整组确认一般流程，整批复核后写入。
5. 审批生效每只股票独立批次，仅通过 20 后更新当前池。

目标池与候选股票查询

批量入口负责目标池与多股票编排，业务校验和后续审批复用股票单笔链路。

POST /api/v1/batchStockPoolAdjust/queryPoolPage POST /api/v1/batchStockPoolAdjust/queryStockPage POST /api/v1/stockPoolAdjust/queryIndustryList POST /api/v1/common/queryPoolTreeList

目标池查询

  • queryPoolPage 传 currentUserId / poolIds / pageIndex / pageSize，仅展示有调整权限、启用、未删除且支持 stock 的叶子池；管理员口径与单笔一致。
  • 列表包含池全路径、描述、市场、品种、容量上限及有效股票数量；有效数只统计 ip_pool_status_stock.audit_status=20、未删除的不同股票代码。
  • 选定一个目标池和 direction=in/out 进入两步工作台；池列表与末尾分页为固定底栏保留空间。

候选股票查询

  • queryStockPage 传当前用户、目标池、方向以及 stockCode / stockShortName / industryCode / marketCode / pageIndex / pageSize；行业选项沿用股票单笔接口。
  • 候选固定未删除、security_status=L、股票品种、市场 SSE / SZSE / HKEX，且未到退市日期。调入排除目标池有效成员，调出仅保留有效成员。
  • 列表展示代码、简称、行业、市场、最新评级、上次评级、昨收及数据日期；市场和评级走前端字典及标签，空值留白、零值显示。评级按 rating_date DESC, id DESC 取最近两次未删除记录；buy / overweight / neutral / underweight / sell 分别展示买入 / 增持 / 中性 / 减持 / 卖出，无评级留白。
  • 勾选按股票代码跨页保留，可逐项移除或清空；快速翻页、退出或切换目标池后忽略迟到响应，不覆盖新结果或加载状态。

批量校验与提交

允许提交通过的完整股票组；整批提交使用一个事务，任一最新复核或写入失败全部回滚。

POST /api/v1/batchStockPoolAdjust/checkAdjust POST /api/v1/batchStockPoolAdjust/addAdjustLog POST /api/v1/batchStockPoolAdjust/addAdjustLogWithFiles POST /api/v1/reports/queryInReportPage POST /api/v1/reports/queryOutReportPage

逐股票校验与页面展示

  • checkAdjust 传 currentUserId / poolId / direction / stocks:[{stockCode}]；逐股票调用 StockPoolAdjustService.checkAdjust。
  • 复用状态、品种市场、权限、评级行业、容量、当前在池、在途、来源、联动互斥、开放日和冻结期；报告限制在提交及终审按单笔复核。
  • 每只股票恰有一条手工主项，组键 <stockCode>_stock-group-1，完整关系项同组；组内任一项失败则整组不可提交，其他通过组可提交，反向互斥项不可丢弃。
  • 只提供目标池 normalInbound / normalOutbound；主项选择服务端候选，关系项共用主项流程，快速和批量专用流程不可选。
  • 统一原因与建议选填，页面各最多 500 字；返回第一步保留选择与材料，修改选择使旧校验失效，重新校验刷新结果；提交中禁止重复操作。

提交和审批

  • addAdjustLog 为 JSON；有本地文件时走 addAdjustLogWithFiles，multipart 为 request / files / originalFileNameListJson，中文原名数组与上传顺序和数量一致。
  • 根参数 currentUserId / poolId / direction / adjustReason / adjustAdvice / adjusterId / adjusterName / items；调整人与当前用户须一致。根方向 in/out，明细 adjustMode 为“调入/调出”。
  • 每项增加 stockCode，保留 targetPoolId / itemTag / adjustGroupKey / flowId / flowKey / flowType 与报告、材料的文件索引和来源引用；拒绝伪造分组、重复股票、遗漏关系和错误流程。
  • 一次按主档主键顺序锁定整批股票，再按池 ID 升序锁池；全部组复核后保存日志、附件与步骤，使用 READ_COMMITTED 事务；失败整批回滚并清理本次共享文件。
  • 主项服务器标记“手动批量调整”，关系项仍为联动/互斥；每股票一个 STOCK 批次。返回 stockCount / submitCount / logIds / adjustBatchNos，股票数去重，日志数包含全部关系项。
  • 成功回池列表并刷新；待办、驳回修改、撤回与详情沿用股票链路，仅状态 20 落池，终审继续复核报告、评级、权限及容量。

报告选择与共享材料

  • 内部/外部报告双页签保留标题、证券编码、类型、日期、分页、跨页勾选、下载及已选汇总，调用报告库原有接口。
  • 研究报告须为股票品种且 securityCode 匹配已选股票；按代码分配到对应股票完整组，不匹配报告明确提示。
  • 本地报告和其他材料整批共享；同股票主项及全部关系项复用报告来源。服务端按集合核对整批本地索引/材料以及同股票报告引用，不一致在写入前拒绝。

附件绑定与终审复核

  • 共享上传只保存一份物理文件，再按每条股票日志分别绑定；表固定 ip_adjust_log_stock，分类 stock_report_hand/in/out、stock_material_hand/in/out。
  • 四类附件字段为 reportFileIndexes / materialFileIndexes / reportSourceAttachmentIds / materialSourceAttachmentIds；报告与其他材料分别处理。
  • 沿用 none / any / internal 报告要求、股票归属和来源有效性，提交与终审再次验证；审批完成后按债券方式沉淀内部报告。

关键规则与当前实现说明

与当前股票业务实现一致的状态、权限及数据边界。

  • 股票单笔一般/快速流程不变；批量只接受目标池一般流程，不能照搬债券或基金的其他流程候选策略。
  • 校验返回 items / stockCount；完整通过组才能提交，关系项、反向互斥项和材料不能遗漏。部分组可选不代表提交事务可部分落库。
  • 分管关系不授予调整权限；池权限、报告、市场品种、评级与关系规则在提交及终审继续复核。
  • -1 无效 / 00 流程中 / 11 驳回待修改 / 20 审批通过 / 21 审批驳回 / 32 自动处理预留 / 99 发起人已撤回；仅 20 更新当前池状态。
  • 复用现有股票表，无新增表、迁移或 SQL；验证覆盖候选方向、权限、失败组隔离、完整关系、一般流程、共享文件、报告归属及整批回滚。
