业务流程总览

从页面操作到数据库读写的主要路径。

1. 进入待办/详情股票业务域定位日志、批次和待处理步骤。
2. 加载资料读取实时股票、当前池、申请组、审批记录及附件。
3. 权限与校验核实待办处理人、步骤状态和批次上下文。
4. 处理或重提审批、驳回或发起人修改后重提，原子更新步骤及附件。
5. 整组结束沿固定版本路由；通过前复核并落池，详情只读可导出 PDF。

查询、校验与操作逻辑

审核与详情使用同一股票数据链路；审核操作由当前步骤、实际处理人和固定流程版本决定。

审核页面加载

  • 我的事宜以 businessDomain=stock / businessScene=stockAdjust 分发至股票服务，携带日志、批次及步骤定位。股票待办不是债券日志的别名。
  • 依次加载 queryStockDetail / queryStockPoolStatus / queryAdjustLogList / queryAdjustStepList，日志和步骤以批次优先，展示本组主项及关系项。
  • 读取当前用户角色、待办归属和附件，操作按钮由当前步骤与页面模式决定；直接入口仍须经过服务端权限校验。

实时股票信息与只读详情

  • 审核与详情统一展示 15 项基础信息：股票简称、股票代码、所属行业、市场、昨收、最高、最低、平均、换手率、交易总量(手)、交易市值(万)、总股本(百万)、总市值(百万)、流通A股(百万)、A股市值(百万)。
  • 基础信息实时读取 rrs_stockinfo；空值留白，零值正常显示。换手率原值 1.25 展示 1.25%，不再乘 100；交易市值为当日成交金额，币种跟随市场；港股交易量按来源的“手”展示。
  • 评级按 rating_date DESC, id DESC 取最近两次未删除记录；buy / overweight / neutral / underweight / sell 分别展示买入 / 增持 / 中性 / 减持 / 卖出，无评级留白。
  • 历史申请名称、行业及评级以日志留痕为准；实时基础区域不代表提交时行情。详情展示当前池、调整组、步骤和报告材料，只读不触发新调整。

导出 PDF

  • 审核和详情复用 js/print_export.js，输出基础信息、当前所在池、调库明细、审批流程及报告材料区域。
  • 使用当前已加载数据生成打印/PDF 视图；隐藏操作、上传等交互控件，保留内容与文件名称，数值空白和市场单位沿用页面。
  • 调库记录中的调整类型、调整方向、审核状态列在导出 PDF 时沿用债券研究的竖排表头和标签样式，避免标签超出单元格；页面浏览时仍横向显示。
  • PDF 导出只读，不保存申请、不推进步骤，不改变当前池状态。

并发与权限校验

  • submitAdjustAudit / submitAdjustAuditWithFiles 传 stepId / adjustLogId / adjustBatchNo / handlerId / handlerName / processAction / processComment。
  • 核实日志、批次、步骤相互匹配且待处理；实际处理人或管理员才可操作，管理员优先定位自己的待办。非管理员发起人不能越过普通后续审批，仅发起人语义节点允许。
  • 先锁股票，再重读待办；步骤条件更新防重复处理。上下文不匹配、已办步骤或越权明确失败，前端隐藏按钮不是安全边界。

会签与抢占

  • ALL 要全部同意后继续；其他策略按先处理结果决定路由，其余未处理步骤作跳过处理。
  • 抢占在实际审批事务内完成，不存在额外“认领”接口。并发操作由锁及待处理状态条件保护，后到操作不能覆盖已办结果。
  • 审批读取当前步骤 flow_node_id 所属版本，再按该版本节点/边推进；新发布流程版本不替换在途申请路由。

修改后重提

  • 11 且当前节点具有发起人语义时允许修改原因建议并重提；同意提交的原因建议接口最多 1000 字，审批意见与原因建议分开保存。
  • 可按允许范围修改本组报告材料，校验旧附件归属、分类、来源和新文件索引；修改与步骤推进在同一事务完成。
  • 普通驳回必须填写意见并确认；路由进入 11 或最终 21，已在 11 时驳回并结束为 99。重提继续按原版本流程处理。

流程结束与最终复核

  • 到达通过结束前，按整组最新数据复核股票、池状态、市场品种、权限、行业评级、来源/联动互斥、开放日、冻结期、报告和容量；任一失败不落池。
  • 全部通过后日志统一置 20，入池新增有效成员，出池逻辑移除成员；驳回和撤回只更新日志/步骤。
  • Excel 导入/清空主项在终审及驳回修改重新提交时也复核最新报告要求，未改附件不能绕过规则变化。

附件与报告处理

  • 列表/下载走 /api/v1/attachments/queryAttachmentList / downloadAttachment，固定股票业务域及 ip_adjust_log_stock 主表。
  • attachmentChanges 按日志携带报告/材料文件索引、来源附件 ID 和删除 ID；逐项验证归属、股票代码、分类与可操作批次。
  • 报告仍需满足 none / any / internal 与同股票归属；已有内部/外部报告和本地新文件分别核验。
  • 有新文件使用 multipart 接口，原始文件名统一携带；失败回滚数据库更新并清理本次新增物理文件。

关键规则与边界

与债券审核保持同类说明结构，同时保留股票独立的数据、权限和流程约束。

乐观并发与处理人

  • 步骤必须仍待处理，条件更新只允许一次有效处理；整组业务复核和推进受股票锁保护。
  • 管理员例外由公共管理员判断解析，业务入口角色控制不能替代待办归属判断。

审核状态机

  • -1 无效 / 00 流程中 / 11 驳回待修改 / 20 审批通过 / 21 审批驳回 / 32 自动处理预留 / 99 发起人已撤回；仅 20 更新当前池状态。
  • 11 是待修改状态，不是已出池或已入池；32 仅预留，不能当作审批通过。

固定版本与原子提交

  • 审批沿运行步骤所属版本，发布新版本不重建在途流程；附件、日志、步骤及最终池状态保持事务一致。
  • 最终落池必须再次检查当前规则和整组关系，不能只复用申请时检查结果。

详情入口与返回

  • 股票查询使用来源日志 adjustLogId；历史使用真实日志 id，禁止将当前池状态主键当日志 ID。
  • 工作台按股票业务、股票代码及日志/批次/池复用详情页签，与债券、基金隔离；返回关闭当前详情页签并回到来源。

业务入口与处理范围

审核入口、只读详情与申请入口职责清楚，避免把详情查看等同于可执行调库。

审核入口

  • 从我的事宜进入当前股票待办；工作台直接入口按用户和角色配置展示，服务端仍复核实际待办及管理员权限。
  • 处理普通人工审批、会签/抢占、驳回与修改后重提；单笔、批量和 Excel 申请共用股票审核链路。

详情与申请边界

  • 查询/历史可打开 pages/stock_pool_adjust_detail.html 查看完整批次，下载附件并导出 PDF，不显示审批提交或申请选池操作。
  • 新申请在单笔、批量或 Excel 页面发起；详情和审核不提供债券发行主体财务数据，使用股票实时基础信息。

关键规则与当前实现说明

与当前股票业务实现一致的状态、权限及数据边界。

  • 股票表、业务域与附件绑定必须完整匹配；与其他业务同编号的日志、步骤或附件不得串用。
  • 分管关系只服务查询筛选，不是审核授权；个人自选不改变正式池状态，也不参与当前待办处理人判断。
  • 股票 SQL 在后端 sql/stock/，结构与 Demo 成对维护；前端业务文档和业务页面均不执行初始化或清库。
