定时任务管理

在「RRS配置」下可视化维护任务配置（名称、说明、Cron、启停、扩展参数），支持手动执行与执行历史；业务实现与库表配置分离，扩展参数统一为 JSON。不同 taskCode 之间无编排，有池状态依赖必须靠 cron 先后（见需求 29 第 4.1 / 4.2 节）。

业务流程总览

从页面操作到调度挂载、业务执行与历史落库的主要路径。

1. 维护配置新增/编辑/删除任务行：名称、说明、Cron、启停、param_json。
2. 写库与审计落 sys_scheduled_task，并写 sys_scheduled_task_evt（oprt_type=INSERT/UPDATE/DELETE）。
3. 动态挂载已启用且已有 RrsScheduledTask 实现时挂载 DynamicTaskScheduler。
4. 执行业务手动或 Cron 触发；同 taskCode 串行；不同任务无编排，有依赖须靠 cron 先后（先到期、再改主体、最后同步债）。
5. 历史与摘要更新主表最近执行摘要，并插入 sys_scheduled_task_run_log。

配置维护与动态调度

配置只认库表；代码侧只注册 taskCode 与 execute 实现。

POST /api/v1/scheduledTask/queryTaskPage · queryTaskList · queryTask · addTask · editTask · deleteTask

列表与详情

  • 仅查未删除的 sys_scheduled_task，不按代码种子写库。
  • 列表分页：queryTaskPage（关键字匹配名称/编码，可按调度启停筛选），默认每页 20 条。
  • 展示字段含 cron、启停、param_json、最近执行摘要。
  • codeRegistered：Spring 是否已注册同编码 RrsScheduledTask。
  • paramHelp：已注册实现时由 getParamHelp() 提供；后端以 [[TOOLTIP]] 前缀标记仅悬浮展示的行，配置页正文显示其余内容，标题旁提示图标展示参数示例、配置含义和字段说明。

新增 / 修改 / 删除

  • 新增：编码格式校验、唯一；写主表 + 审计 INSERT；满足条件则挂载调度。
  • 修改：编码不可改；更新名称/说明/cron/启停/参数；审计 UPDATE；按最新值重挂或取消。
  • 删除：逻辑删除并关闭调度；审计 DELETE；取消已挂载 Future。
  • 无业务实现也可先建配置；执行时才校验是否已注册实现。

执行、过程日志与历史

手动与定时共用同一执行入口与落库逻辑。

POST /api/v1/scheduledTask/executeTask · queryRunLogPage

执行

  • 须有库表配置 + RrsScheduledTask 实现，否则业务失败提示。
  • 触发方式：manual（页面）/ cron（调度器）；操作人定时为系统。
  • 同 taskCode 串行锁，避免重叠跑。
  • 扩展参数非法（非 JSON、缺必填字段等）记失败，不记成功 0 条。

过程日志与历史

  • 业务侧用 TaskDetailLog 采集过程行（带 yyyy-MM-dd HH:mm:ss 前缀）。
  • 结果写入 ScheduledTaskResult.detailLog，落库 run_log.detail_log。
  • 同时更新主表 last_run_* 摘要字段。
  • 历史分页：queryRunLogPage；页面可点「过程日志」查看全文。

内置任务与扩展参数

param_json 仅 JSON 对象；框架不解析，各任务自行解析并由 getParamHelp 说明。卡片按 Demo cron 执行顺序排列。

执行顺序（只约束 cron）

  • 不同 taskCode 无编排、无全局锁，先后全靠 cron；列表 id 不要求与顺序一致。
  • 02 到期债/股出 → 03 CRMW 到期出 → 04 外评出主体 → 05 外评入主体 → 06 同池入债 → 07 Job 入债 → 08 主体不在池出债 → 09 不符合分级规则提醒。
  • wind_code_sync 与三项恒生池 Excel 导出任务不改池状态，不插入上序，可并行。
  • 页面「立即执行」不校验顺序。完整规则见需求 29 第 4.1 / 4.2 节。

恒生池全量数据导出（不含已到期） hs_pool_full_excel_export

  • 每天 01:10 执行（Cron：0 10 1 * * ?；Demo 默认关闭）
  • 参数示例：{"poolIds":[15,16],"exportEmptyPool":true,"outputDir":"D:/exports"}；poolIds 省略或为空时导出全部叶子池。
  • 导出当前已生效的非主体证券和 CRMW；普通证券排除已到期数据，CRMW 按老系统定时任务口径不校验到期日。
  • 恒生池名称为空时使用投资池完整名称，竖线可拆分多个 Sheet；同名 Sheet 合并并记录警告。市场使用中文名称并按多个市场代码字段拆行，该口径后续再确认。
  • 文件写入输出根目录下的 yyyyMMdd 日期目录，同时复制到 bak；FTP 暂未接入。

恒生池全量数据导出（含已到期） hs_pool_full_including_expired_excel_export

  • 每天 01:20 执行（Cron：0 20 1 * * ?；Demo 默认关闭）
  • 参数与不含已到期全量任务一致：poolIds、exportEmptyPool、outputDir。
  • 导出当前已生效的非主体证券和 CRMW；普通证券包含仍在池的已到期数据，CRMW 不校验到期日。
  • 对应老系统 ExportStatusToHsJob2；文件使用独立前缀 hs_pool_full_including_expired，避免与 01:00 文件重名。
  • Sheet、市场拆行、日期目录和 bak 备份规则与不含已到期全量任务一致；FTP 暂未接入。

恒生池增量数据导出 hs_pool_increment_excel_export

  • 每 6 分钟执行一次（Cron：0 */6 * * * ?；Demo 默认关闭）
  • 首次以参数 initialStartTime 为下界；后续以上次成功执行开始时间为下界、本次开始时间为上界。
  • 导出窗口内审批通过的调入和调出事件，不要求证券当前仍在池；调出操作类型写“删除”。交易日列表入口已预留，当前列表为空，因此交易日和非交易日均正常执行。
  • 老系统通过调库日志 exportflag 控制增量；新系统使用任务成功时间水位线，不更新业务调库日志。市场继续使用中文名称。
  • poolIds、exportEmptyPool、日期目录和 bak 备份规则与全量任务一致；不更新业务调库日志。

到期证券自动出池 security_expired_auto_out

  • 每天 23:00 执行（Cron：0 0 23 * * ?；Demo 默认关闭）
  • 参数：{"poolIds":[15]} 或 {"poolIds":[10,15]}
  • 扫描所列投资池中 audit_status=20 的债/股，主数据到期日早于昨天（T-2）则自动调出（不含主体/基金/CRMW）；当前在调出限制池则跳过；仅软删成功才写日志（自动调整、不走审批）。

CRMW到期自动出池 crmw_expired_auto_out

  • 每天 23:05 执行（Cron：0 5 23 * * ?；Demo 默认关闭）
  • 对应老 IP_RULE AdjustRuleCrmwDueOutPool
  • 参数：{"poolIds":[18]}
  • CRMW 池已生效组合、凭证到期日早于昨天（T-2）→ 自动调出；调出限制池阻断；仅软删成功才写日志。

外评非AA-及以下主体自动出池 company_outer_rating_not_aa_minus_auto_out

  • 每天 23:10 执行（Cron：0 10 23 * * ?；Demo 默认关闭）
  • 参数：{"poolIds":[16],"limitPoolIds":[15]}
  • 有效外评（近 12 个月取档）不在 AA-/A/BBB… 则出主体，并顺带出同池债；已在 limitPoolIds（默认禁投池）则不出；调出限制池阻断。

外评AA-及以下主体自动入池 company_outer_rating_aa_minus_auto_in

  • 每天 23:15 执行（Cron：0 15 23 * * ?；Demo 默认关闭）
  • 参数：{"poolIds":[15]}
  • 有效外评（近 12 个月取档）在 AA-/A/BBB…（不含 AA/AA+/AAA）且未在目标池 → 自动入主体；调入限制池阻断。

主体下债券自动入库 company_same_pool_bond_auto_in

  • 每天 23:20 执行（Cron：0 20 23 * * ?；Demo 默认关闭）
  • 对应老系统 IP_RULE type=0「主体下债券自动入库」
  • 参数：{"poolIds":[15]}（主体与债必须同一池，无 mappings）
  • 主体已在本池 → 旗下债未到期（含当天）未在本池 → 同池自动入；尊重 market_codes；不排除临时代码/ABS；调入限制池阻断。

在池主体旗下债券自动入池 company_inpool_bond_auto_in

  • 每 10 分钟执行一次（Cron：0 */10 * * * ?；Demo 默认关闭）
  • 对应老系统 AutoAdjustInNewBondToLimitPoolJob
  • 同池：{"poolIds":[15]}；跨池：{"mappings":[{"companyInPoolId":15,"bondTargetPoolId":100}]}
  • 主体已在池 → 旗下债未到期（不含当天）、尚未在目标池则入；排除临时代码已更新、ABS、CRMW；不看限制池。

主体不在池债券自动出池(默认关闭) company_not_in_pool_bond_auto_out

  • 每天 00:00 执行（Cron：0 0 0 * * ?；Demo 默认关闭，建议按需手动执行）
  • 对应老 AutoAdjustInLimitPoolToNewBondJob
  • 参数：{"poolIds":[15]} 或 {"mappings":[{"bondPoolId":15,"companyPoolId":15}]}
  • 债已在债券池、主体不在主体池 → 出债；排除 ABS/CRMW（ABS 走禁投独立链路）；不看限制池。

不符合主体债入库规则提醒 bond_grade_inconformity_alert

  • 每天 01:00 执行（Cron：0 0 1 * * ?；Demo 默认关闭）
  • 对应老 InconformityMaingrade2Job（每天 9 点提醒，不自动出池）
  • 无需 param_json。扫描已在信用债 1～5 级但按当前特殊债规则不再允许的债券（不含境外债），写入 ip_grade_rule_alert 待办。
  • 执行摘要区分：本轮命中 / 本轮失效（曾待处理、本轮未再命中）/ 仍待处理；影响条数取仍待处理。
  • 人工在「我的事宜」分级规则提醒页签去调库或标记已处理。

Wind代码变更同步 wind_code_sync

  • 每 10 分钟执行一次（Cron：0 */10 * * * ?；Demo 默认关闭）
  • 作用：将临时代码同步为正式代码。入口不是「临时代码管理」页的人工更新，但逻辑一致，复用同一套更新方法；部分临时代码可能未经过管理页，而是 Wind 变更后直接在库中把临时代码更新为正式代码，由本任务扫描落业务数据。
  • 实现类 WindCodeSyncService（空壳，后续迁入公司逻辑）。无需 param_json。与自动调库无池依赖，不插入 02～09 顺序链。
  • 新增任务步骤：① 先评估执行顺序（需求 29 第 4.1 / 4.2 节）再定 cron；② 页面新增配置记下 task_code；③ 实现 RrsScheduledTask 并覆盖 getParamHelp；④ 部署后执行。
  • 不同 taskCode 无全局锁。Demo：23:00 到期债股 → 23:05 CRMW 到期 → 23:10 外评出主体 → 23:15 外评入主体 → 23:20 同池入债 → 次日 00:00 主体不在池出债（默认关闭）→ 次日 01:00 不符合分级规则提醒；company_inpool_bond_auto_in 每 10 分钟执行，会在部分时刻与固定任务同秒触发；另 wind_code_sync 与三项恒生池 Excel 导出任务不改池状态。
  • 演示数据：rrs_scheduled_task_demo_data.sql（脚本工具可初始化；cron 须与上述执行顺序一致，列表 id 不要求）。

涉及表、用途与触发场景

读写口径包含配置维护、调度摘要与执行历史。

表名 用途 主要读写 触发场景
sys_scheduled_task 任务配置主表：编码、名称、说明、cron、启停、param_json、最近执行摘要 读 写 改 列表/详情/新增/编辑/删除；每次执行后更新 last_run_*
sys_scheduled_task_evt 配置变更审计（含 oprt_type：INSERT/UPDATE/DELETE） 写 addTask / editTask / deleteTask
sys_scheduled_task_run_log 执行历史：状态、摘要 message、过程日志 detail_log、触发方式、操作人 读 写 手动执行 / 定时触发；历史分页查询
  • 建表与演示脚本：sql/rrs_scheduled_task_schema.sql、rrs_scheduled_task_demo_data.sql（已注册 ScriptTool）。
  • 若已有库表缺 detail_log：ALTER TABLE sys_scheduled_task_run_log ADD COLUMN detail_log TEXT ...（见 schema 文件注释）。

规则说明与代码索引

实现约定与排查入口。

规则要点

  • 全部接口 POST，前缀 /api/v1/scheduledTask，返回 ApiResponse。
  • 扩展参数仅 JSON；业务失败（参数非法等）历史记 fail，不把「跳过」当成功。
  • 关闭「启用调度」后仍可手动执行。
  • 前端页：pages/scheduled_task.html（RRS配置菜单）。
