CRMW池批量调整

页面与证券池批量调整同构。仅展示 CRMW 叶子池；候选为凭证+标的组合；逐组合委托 CRMW 单笔校验/提交，整批事务落 ip_pool_status_crmw。

业务流程总览

从页面操作到数据库读写的主要路径。页面为单页两步工作台（池列表 → 选组合/校验/提交），交互对齐证券池批量调整。

1. 选择目标池仅 CRMW 叶子池。按可调整权限查询，操作列调入/调出进入工作台。
2. 筛选组合步骤1：选凭证+标的组合+材料；调入排除已在池组合，调出仅已在池组合；滚动区为固定底栏预留空间，分页保持可见。
3. 批量校验步骤2：逐组合复用 CRMW 单笔校验，展示结果表与材料汇总。
4. 批量提交整批事务按组合分组写申请/步骤/附件，统一 submit_time。
5. 审批生效仅 audit_status=20 落 ip_pool_status_crmw；直通亦先锁池复核。

目标池与候选组合查询

先选有权限的启用 CRMW 叶子池，再按调入/调出分别查询凭证+标的组合。

POST /api/v1/batchCrmwPoolAdjust/queryPoolPage · queryInboundCandidatePage · queryOutboundCandidatePage

目标池查询

  • 筛选树 includePoolTypes=['crmw']；列表 SQL 固定 pool_type='crmw'。
  • 管理员可查看全部 CRMW 叶子池；普通用户依据 ip_pool_permission 的 adjustable 权限过滤。
  • 只返回 status='enabled'、未删除且没有启用子节点的叶子池。
  • 现有数量统计 ip_pool_status_crmw 有效组合数，分项 typeCode=crmw，并回填完整池路径。

候选组合查询

  • 目标池必须存在、启用、为 CRMW 叶子池且当前用户有调整权限。
  • 调出走 queryOutboundCandidatePage：ip_pool_status_crmw 当前有效组合，左连标的证券主数据。
  • 调入走 queryInboundCandidatePage：CRMW 凭证 × 可绑定标的（排除 crmw/company）且该组合尚未在目标池。
  • 候选表列：证券名称/代码、市场、CRMW名称/代码、发行人、证券评级、主体评级、主体内评分档、到期日期、剩余期限(年)、担保人*。
  • 跨页多选键为 crmwScode|securityCode。

批量校验与提交

批量层负责聚合，规则与 CRMW 单笔调库一致。步骤2校验结果列：证券名称、证券代码、CRMW名称、CRMW代码、投资池名称、调整类型、调整方向、审批流程、调整说明、校验结果。

POST /api/v1/batchCrmwPoolAdjust/checkAdjust · addAdjustLogWithFiles

逐券校验与页面展示

  • 每个组合转换为单笔 AdjustCheckReq（含 crmwScode/crmwStype/crmwName），调用 crmwPoolAdjustService.checkCrmwAdjust，复用 CRMW 组合校验、联动互斥扩展与反阻断。结果项身份、流程候选与 warnings 透传单笔返回。
  • 调入/调出顺序与 CRMW 单笔 checkInConditions / checkOutConditions 一致：目标池必须是 CRMW 池；已在池按凭证+标的组合判断；弹性禁投写 warnings 不阻断。CRMW 单笔不走主体债入库矩阵，也不消费 releaseRules / fundRate。
  • 页面工作台保留与证券池批量相同的「是否放开规则」和「担保人*」控件（多担保人默认不选、下一步必选）。批量编排层把每个标的的 guarantorCode 透传到单笔校验与提交，用于关系复核、担保人评级下调判断及申请快照保存；releaseRules=yes 仅在提交时把「放开主体债入库矩阵规则」追加到调整意见/调整说明。
  • 流程候选与推荐完全透传单笔 checkCrmwAdjust，不再注入目标池 batchIn/batchOut；前端默认选中 recommended，操作员可改选。
  • 步骤2 chips 汇总报告/附件/放开规则/条数；「调整说明」失败分条展示 failReasons，警告展示为「可调整(警告)」；同组 adjustGroupKey 底色区分。流程确认弹窗标题同时展示标的与 CRMW 凭证，避免同标的不同凭证混淆。

提交和审批

  • 整个批量请求一个事务，任一失败全部回滚；约 30 秒窗口内防重复提交（按凭证+标的集合+手工项+流程+原因意见比较）。
  • 提交流程透传前端按单笔候选所选 flowId/flowKey/flowType，不再回填 batchIn/batchOut。前端须为可提交手工项选定流程候选（含「无需审批」/空 flow 直通）；后端允许空流程直通。
  • 按触发主组合（crmwScode|securityCode）分组后调用单笔 submitAdjustLog；共享 SubmissionFiles 与 BatchNoContext；手工项 adjustType=手动批量调整；批次号前缀仍为 CRMW。
  • 批量 multipart 提交在共享 files 外携带同序 originalFileNameListJson，后端据此保留中文原始文件名；未传数组时回退 multipart 文件名，数组数量与文件数不一致时直接拒绝提交。
  • 存在直通项时：先 isDirectAdjustFlow 判定，再整批 recheckBeforeFinalApproval。子集与单券终审一致——调入：池锁/已在池/品种/来源/限制/禁投/容量；调出：池锁/未在池/限制/冻结；不重跑开放日/矩阵等（见证券池调库「校验分层」）。
  • releaseRules=yes 不改变 CRMW 单笔校验（无主体债矩阵可跳过），只追加调整意见/说明文本；容量/来源/硬限制等仍执行。
  • 后续审批复用 CRMW 池调库审核页（会签/抢占/驳回/终态落 ip_pool_status_crmw）。

关键规则与当前实现说明

  • 批量不是一条总申请：后端按凭证+标的组合分组，再为手工、联动、互斥明细分别保存调库日志。
  • 方向只允许 in 或 out；手工明细方向必须与本次批量方向一致。
  • 可提交手工项须选定流程候选（含直通选项）；联动/互斥项复用同组手工项流程与批次号。
  • 仅 audit_status=20 落地 ip_pool_status_crmw；弹性禁投为警告不阻断，与单笔一致。
  • 步骤2原因/建议为整批共享文案，与单笔调库页「每组合可回填日志原因」场景不同。
  • submit 不整单重跑 checkCrmwAdjust；直通/终审仅 recheck 动态子集。细节见 CRMW池调整。
  • 与 Excel 导入差异：本页不注入 batchIn/batchOut；Excel 仍可能把目标池批量流程置顶推荐。
