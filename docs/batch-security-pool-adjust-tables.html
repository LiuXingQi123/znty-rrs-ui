业务流程总览

同券跨市场按调库组整体校验。每个同券市场代码单独显示一条校验记录。退市、到期或调出时不在目标池的关联码保留在结果中，该行不可调整并显示原因。其余有效码继续按组校验，任一有效码命中在途等阻断规则时，有效组不可提交。明确选中的主券到期时仍展示各市场结果，本组不可提交。其他独立调库组不受影响。“放开规则”沿用主券本次选择，所有关联券一致跳过既有主体债入库矩阵；在途流程、市场、品种、到期、容量及其他硬限制仍逐券校验。后端按当前同券范围核对单笔调入明细，批量及 Excel 复用校验后的实际代码集合。普通调库提交及终审逐码复核调入，实际提交的代码到期时要求重新校验整组。Excel 提交及终审沿用到期作为调整提示的口径。逐券活动流程检查继续执行。

从页面操作到数据库读写的主要路径。页面为单页两步工作台（池列表 → 选券/校验/提交），不依赖独立选择页回传。

1. 选择目标池按可调整权限查询投资品种包含债券的启用信用债叶子池。筛选树默认收起。
2. 筛选证券步骤1：选券+材料；调入排除已在池，调出仅已在池；滚动区为固定底栏预留空间，分页保持可见。
3. 批量校验步骤2：展示逐券校验结果与材料汇总，默认勾选全部可调整项。
4. 批量提交仅提交勾选项，按证券分组在同一事务内写申请、步骤和附件。
5. 审批生效仅 audit_status=20 落池；直通依据本次读取的数据复核。

目标池与候选证券查询

可选证券区域支持“主体编码”（issuerCode）和“证券全称”（securityFullName）查询，证券代码、主体编码按前缀匹配，证券全称按包含匹配；留空不限制，与其他条件按 AND 组合。输入框支持回车查询，查询回到第一页，重置时一并清空。表格展示“主体编码”（issuerCode）和“证券全称”（fullName），为空留白；原“发行人”或“发行主体全称”的查询条件和列表列统一显示为“主体全称”（issuer）。重新进入调入/调出时清空上述条件。

“是否特征”支持“是否标准信用债”（bondYesFlags 选项 stdCredit），勾选仅筛选证券主档 std_credit_flag=1，多选按 AND；不勾选不限制。对应表格追加 stdCreditFlag 列，沿用 isYesFlag 先转布尔值：1 显示“是”Tag，其他值（含 NULL）显示“否”Tag；接口与其他标识一样返回原始数值。只使用上游原始标志，不根据其他特征或 std_clause_flag 推断；CRMW 使用标的证券字段。

目标池查询

  • 普通用户依据 ip_pool_permission 的 adjustable 权限过滤，管理员可查看全部符合查询条件的池。
  • 列表只查询 pool_type='credit_bond'、status='enabled'、未删除、没有启用子节点，且 variety_codes 包含 bond 的叶子池。筛选树保留信用债类型下投资品种包含债券的池及其上级，打开时默认收起。
  • 汇总 ip_pool_status 有效在池数量时按类型分项（countByType：主体/CRMW/债券等）：用池状态 security_type 关联字典大类，不经 rrs_securityinfo；前端多行展示「类型：n只」；并回填完整池路径。

候选证券查询

  • 目标池必须存在、启用、为叶子池且当前用户有调整权限。
  • 调入使用 NOT EXISTS 排除目标池有效状态；调出使用 EXISTS 仅保留目标池有效状态。
  • 调入、调出均支持主体编码、主体全称、证券代码、简称、全称、市场和“是否特征”过滤；主体全称通过 issuer 入参仅按名称模糊匹配，与其他条件按 AND 组合，留空不限制；点击查询或在主体全称输入框按回车回到第一页，重置及重新进入工作台时清空主体全称条件。特征可多选 ABS/担保/永续/次级/私募/含权/标准信用债，勾选即筛“是”、多选 AND；候选包含 CRMW 凭证，排除主体。CRMW 池的调入和调出候选沿用现有的在池状态与查询条件。
  • 候选表以“是/否” Tag 展示六项证券特征，私募按发行方式或内部分类含“私募”判定，ABS 兼容 abs_flag=1 或证券类型 abs。
  • 候选证券查询无固定 ORDER BY，分页顺序不作保证；跨页多选由前端 selectedSecurityMap 缓存。

批量校验与提交

强担保豁免开关：统一使用 common/constants/BusinessSwitches.java 中的代码常量 BusinessSwitches.STRONG_GUARANTEE_ENABLED，当前为 false。改为 true 可恢复豁免，修改后需重新编译并重启服务生效。关闭时，非 ABS 担保人内评 1 档也执行重点观察名单限制；开启时恢复原有重点观察名单准入及池间 in_restrict 豁免。普通担保债评级矩阵不变，ABS、禁止池及其他限制池不享受该豁免。

提交和审批

  • 整个批量请求一个事务，任一失败全部回滚。正式提交按在途和在池状态复核。
  • 已勾选的组须带齐该组可调整的手工、联动、互斥及跨市场关联项。缺项时页面提示补勾，补齐后才可提交。
  • 流程确认弹窗只显示已勾选的手工项，并要求为这些项选定流程（含「无需审批」）。提交透传所选 flowId、flowKey、flowType，后端允许空流程直通。
  • 按触发主券（sourceSecurityCode）分组后调用单券 submitAdjustLog（非本类落库）；共享 SubmissionFiles 与 BatchNoContext；手工项 adjustType=手动批量调整。
  • 批量 multipart 提交在共享 files 外携带同序 originalFileNameListJson，后端据此保留中文原始文件名；未传数组时回退 multipart 文件名，数组数量与文件数不一致时直接拒绝提交。
  • 普通债独立调入共用提交批次的主档及流程快照，集中读取评级主体、在池、在途和容量。ABS 默认主体也按本次从数据库查询的候选确定。
  • 存在直通项时：先 isDirectAdjustFlow 判定，再整批 recheckBeforeFinalApproval。子集与单券终审一致——调入：池锁/已在池/品种/来源/限制/禁投/容量；调出：池锁/未在池/限制/冻结；不重跑开放日/矩阵等（见证券池调库「校验分层」）。
  • releaseRules=yes 仅跳过主体内评×期限矩阵，容量/来源/硬限制等仍执行。
  • 调入信用债大库：正式无内评失败；临时代码无内评默认 grade_code=4 再走矩阵。
  • 后续审批复用证券池调库流程服务（会签/抢占/驳回/终态落库）。

快速入库与材料豁免

产品库快速资格适用于 bond_product_root 子树启用叶子。信用债一至三级、转债核心/重点按普通在池记录判断。CRMW 库默认认可 ip_pool_status 的有效记录和 ip_pool_status_crmw.security_code 的有效组合标的，任一命中即可。本次待申请来源不计入资格。

满足快速资格即免除本次信评报告、报告引用及其他附件要求，与选择快速、一般、特殊或批量流程无关。同组联动、互斥和关联市场项跟随主项；关联码逐码判断，任一不符则整组无快速材料豁免。无资格主项和独立调出沿用原材料规则。

行级 materialExemptionType 为 creditBondSimple / productSource，无资格时为空；申请、详情调库、审核页下一步及三个批量入口统一按行级资格提示“本次免提交材料（信评报告及其他附件）”。切换流程不改变资格和提示，详情/审核补齐批量调入、批量调出标签。材料区不显示合同范围确认提示或复选框，现有材料入口及内容保留。

材料豁免跟随主项资格，所选流程决定实际审批。提交时按相同口径复核主券及关联市场代码的产品来源，信用债简易资格沿用校验结果，补充的报告引用仍需验证并保存。

ABS 主体一致性

ABS 在所有有效在库和在途申请中只允许一个主体代码；人工申请审核通过或直通成功入库后永久固定主体代码，全部出清也不更换；主体联动自动入池只生成 audit_status=00 的待确认调库日志，暂不写入 ip_pool_status 和主档五字段，也不形成永久绑定；研究员确认主体后才转为 audit_status=20 并正式入池，成功确认后才固定身份。审核通过才保存主档五字段。任意池主体联动和退出提醒共用同一规则，见ABS 跨池唯一主体与主体联动。

已查询数据复用

候选查询同时返回主体代码、名称、内评、认可机构最新外评及机构，最新外评按评级日期 ann_dt 选取。选择后随校验、提交传递，后端直接取值；单券已加载的证券信息用于校验、提交和快照，财报保存后返回本次记录，不再逐期回查。在库、在途及同一 ABS 主体一致性仍按业务时点检查。

CRMW 进入普通池的方式

CRMW 凭证可在证券池调整、批量调整和证券池 Excel 导入中按单券办理。证券池调整和证券池 Excel 导入开放 CRMW 池作为目标池，证券池批量调整页面查询的目标池类型为信用债。存量证券批量调整也支持凭证，目标限定在债券产品库。单券审批通过后写入 ip_pool_status。凭证与标的组合继续走专用 CRMW 调库，状态写入 ip_pool_status_crmw。证券 Excel 清空出库包含 CRMW 凭证，并保留原有校验提示。
