版本总览

本版本包含两类交付：业务规则代码 + 业务文档对齐代码。

后端信用债无内评限制

  • 正式证券无主体内评分档：可选池去掉信用债大库（含 1～5 级）；调入校验返回「未配置主体内评分档」。
  • 临时代码无内评：仍默认最低档 grade_code=4，再按矩阵筛池/校验（与改前一致）。
  • 覆盖证券池调库与批量调库同源矩阵逻辑；需求文档 04-security-pool-adjust.md 已同步。

文档业务文档与字典对齐

  • 字典值总览 / dict.js：内评分档 8 档、补全枚举、去掉错误证券类型。
  • 债券研究、主体禁投池、CRMW、RRS 配置、审核详情：对照实现修正过时说明与表源错误。
  • 明确两套「内评」：调库矩阵 8 档 vs 规则引擎 1 级～10 级。
  • 债券研究「调入/调出校验」：校验链顺序与代码一致，仅在对应项后备注（已注释）/（空实现）/（当前为空）等。
业务代码提交示例：后端 b7f3d23（无内评正式证券过滤/禁止入信用债 1-5 级，临时代码默认最低档）。 前端文档变更含本页及下列文件清单，可按需单独提交推送。

后端改动要点

入口：证券池 queryAdjustPoolList / inCheckMainGradeRule；批量同源校验。

场景 可选池（filterInboundByGradeRule） 调入校验（inCheckMainGradeRule）
正式证券 · 无内评 去掉全部 pool_type=credit_bond 失败：未配置主体内评分档
临时代码 · 无内评 默认 grade_code=4 再按矩阵过滤 默认 4 再走矩阵
有内评 按「内评分档 × 期限档」矩阵保留允许池 目标池须在矩阵允许列表内
放开规则 / 可转债 / 观察池 可跳过矩阵（与既有逻辑一致） 可跳过矩阵

主要类

  • SecurityPoolAdjustService：选池过滤 + 校验 + 规范化内评 code
  • BatchSecurityPoolAdjustService：批量调入矩阵校验对齐
  • 测例：无内评排除信用债池；临时代码默认档 4 通过矩阵

不改动的链路

  • 禁投池（主体）目标池非 credit_bond，不消费该矩阵
  • CRMW 目标池为 crmw，不跑主体内评矩阵
  • 调出方向不做内评矩阵过滤
