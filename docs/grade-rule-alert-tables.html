不符合分级规则提醒

定时扫描已在信用债 1～5 级、但按当前特殊债规则不再允许待在该档的债券（不含境外债，对齐老 polidEnum），写入待办供人工下调或出库。不自动改池。对齐老系统「债券不符合主体内评分档规则提醒」。

非独立菜单入口=我的事宜第三页签旧页仅重定向
流程总览扫描与待办涉及表规则说明文档目录

入口说明（请先读）

与研究管理菜单、文档分组的关系。

当前产品形态

  • 研究管理 → 债券研究 下没有「不符合分级规则提醒」独立业务页（与文档管理债券研究分组一致）。
  • 业务入口：研究管理 → RRS配置 → 我的事宜 → 第三页签「分级规则提醒」（my_matters.html?tab=gradeRuleAlert）。
  • 扫描任务：定时任务 bond_grade_inconformity_alert（可视化「定时任务管理」配置/执行）。
  • 历史页 pages/grade_rule_alert.html 仅 location.replace 到我的事宜对应 Tab，不单独渲染列表。
  • 本页是业务说明文档，挂在「文档管理 → 业务文档 → RRS配置」下，紧挨「我的事宜」；标题标注「并入事宜」。

能力是否还在

  • 在。表 ip_grade_rule_alert、接口 /api/v1/gradeRuleAlert/*、定时扫描与人工标记/去调库均保留。
  • UI 从独立菜单收敛到「我的事宜」；文档从「债券研究」改挂到「RRS配置」，与业务入口同组，避免误以为债券研究仍有该页。
  • 相关业务问题见：我的事宜新老对比、主体内评分档规则新老对比；业务文档·我的事宜。

业务流程总览

处理入口在「我的事宜」第三页签（非债券研究菜单）。任务编码 bond_grade_inconformity_alert，默认 cron 每天 9 点（Demo 可关闭）。后端接口仍是 /api/v1/gradeRuleAlert/*。

1. 扫描在池已生效且在信用债 1～5 级叶子的债券（不含境外债）。
2. 复用校验调用 evaluateGradedInboundForPool，口径与选池/checkAdjust 相同。
3. 本轮命中不符合则新增或刷新 ip_grade_rule_alert（状态 00）。
4. 本轮失效曾待处理、本轮未再命中（已合规或已不在扫描范围）置 99。
5. 仍待处理执行后统计 alert_status=00；摘要三项分列，影响条数取仍待处理。
6. 人工处理在「我的事宜」分级规则提醒页签去调库或标记已处理。不自动改池。

扫描与待办

对齐老系统 InconformityMaingrade2Job：提醒 + 人工，不是静默出池。

POST /api/v1/gradeRuleAlert/queryAlertPage · editAlertProcessed · 定时任务 execute

扫描口径

  • 私募/永续/次级/ABS 天花板、担保孰高、观察封顶、重点观察禁新增。
  • 观察识别：券自己在 observe，或主体级 security_code = issuer_code 在 observe。
  • 老系统观察是跳过矩阵；新需求改为不高于标准最好档。

待办状态

  • 00 待处理：本轮仍不符合。
  • 20 已处理：人工标记，不改池。
  • 99 已失效：再次扫描已符合。
  • 「去调库」工作台新开证券池调整页签（security_pool_adjust.html?securityCode=），调整页 applyUrlSecurityOrList 读代码并进入该券；脱离工作台回退 href。
  • 业务入口在「我的事宜」，不再单独占菜单。旧页仅重定向。

关键规则与当前实现说明

  • 任务不自动出池，只写待办。处理入口在「我的事宜」分级规则提醒页签，须到证券池调库完成下调或出库后再标记已处理。新开 Tab 仅导航层，公司不兼容时可还原 href。
  • 观察名单：老系统跳过矩阵；新需求按标准最好档封顶。识别含主体级 issuer_code。
  • 证券池调库审核页「改判目标池」下拉同样套重点观察，避免审批绕开预览。
