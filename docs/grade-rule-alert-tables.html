业务流程总览

处理入口在「我的事宜」第三页签（非债券研究菜单）。任务编码 bond_grade_inconformity_alert，默认 cron 每天凌晨 1 点。后端接口仍是 /api/v1/gradeRuleAlert/*。

1. 扫描在池已生效且在信用债 1～5 级叶子的债券（不含境外债）。
2. 复用校验调用 evaluateGradedInboundForPool，口径与选池/checkAdjust 相同。
3. 本轮命中不符合则按证券、当前池、档位和不符合原因生成依据摘要；同券同池已有待处理则刷新该条，同一依据已处理过则跳过，否则新增 ip_grade_rule_alert（状态 00）。
4. 本轮失效曾待处理、本轮未再命中（已合规或已不在扫描范围）置 99。
5. 仍待处理执行后统计 alert_status=00；摘要四项分列（命中 / 沿用已处理 / 失效 / 仍待处理），影响条数取仍待处理。
6. 人工处理普通提醒去调库或标记已处理；ABS 主体联动提醒选择权益人后确认主体，或忽略入池。发行主体下拉与证券池调整页权益人一致：选项展示主体全称、关系类型标签（担保人 / 差额支付承诺人 / 债务主体 / 原始权益人）和最新内评，选中后显示“全称（类型）”。自选权益人弹窗与证券池调整页一致，支持主体编码/全称查询、分页、单选高亮和确认选择。列表支持规则类型筛选，并按扫描批次、规则类型、证券代码、主体上下文和池信息稳定排序。确认主体会把待确认日志转为已生效池状态；忽略入池会将待确认日志置为无效，提醒保留为已处理。

扫描与待办

对齐老系统 InconformityMaingrade2Job：提醒 + 人工，不是静默出池。

POST /api/v1/gradeRuleAlert/queryAlertPage · editAlertProcessed · 定时任务 execute

扫描口径

  • 准入：ABS 担保人内评 1 档只能调入一级库否则至少下调一级（无担保人按其余）；私募发债主体内评 1 档只能调入一级库否则至少下调一级；永续发债主体内评 1 档下调一级（只留那一档）否则至少下调一级；次级 1 档只能调入一级库、2+/2/2- 下调一级（只留那一档）、其余至少下调一级；担保债（覆盖永续等）或已在观察池不得高于矩阵最好档、开到五级；已在重点观察名单禁新增，已在 1～4 级只能去五级。
  • 观察识别：券自己在 observe，或主体级 security_code = issuer_code 在 observe。
  • 老系统观察是跳过矩阵；新需求改为不高于标准最好档。

待办状态

  • 00 待处理：本轮仍不符合。
  • 20 已处理：普通提醒标记不改池；ABS 主体联动提醒确认主体或忽略入池后保留处理记录。处理时会把当时的依据摘要写入 context_key，下一轮同依据不再提醒。
  • 99 已失效：再次扫描已符合。
  • 普通提醒「去调库」先按已处理关闭提醒，再在工作台新开证券池调整页签（security_pool_adjust.html?securityCode=）；ABS 主体联动提醒使用权益人下拉、确认主体和忽略入池，不进入普通调库入口。
  • 业务入口在「我的事宜」，不再单独占菜单。旧页仅重定向。

关键规则与当前实现说明

  • 任务不自动出池，只写待办。处理入口在「我的事宜」规则提醒页签，须到证券池调库完成下调或出库后再标记已处理。新开 Tab 仅导航层，公司不兼容时可还原 href。
  • 已处理沿用：标记已处理和去调库都会把「证券 + 当前池 + 档位 + 不符合原因」压成 context_key 写入待办；下一轮扫描遇到相同摘要直接跳过，不再重复生成。档位、原因或所在池任一变化即视为新问题，仍会重新提醒。
  • 观察池：券或主体已在观察池时，不得高于矩阵最好档、开到五级，不跳过矩阵。识别含主体级 issuer_code。重点观察名单走 checkRestricted，不在类型分支里。
  • 证券池调库审核页「改判目标池」下拉同样套重点观察名单，避免审批绕开预览。

ABS 主体一致性

ABS 在所有有效在库和在途申请中只允许一个主体代码；人工申请审核通过或直通成功入库后永久固定主体代码，全部出清也不更换；主体联动自动入池只生成 audit_status=00 的待确认调库日志，暂不写入 ip_pool_status 和主档五字段，也不形成永久绑定；研究员确认主体后才转为 audit_status=20 并正式入池，成功确认后才固定身份。审核通过才保存主档五字段。任意池主体联动和退出提醒共用同一规则，见ABS 跨池唯一主体与主体联动。
