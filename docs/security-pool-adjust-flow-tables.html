流程总览

按实际代码执行顺序梳理，箭头表示主要业务推进方向。

1

查询与校验

查询证券、当前池状态、投资池关系、权限及候选审批流程，判断是否允许调入或调出。

2

发起申请

每条调库明细写入 ip_adjust_log；存在附件时写入 sys_attachment。

3

创建初始步骤

读取已启用的流程版本、节点、连线和处理人配置，生成 ip_adjust_step。

4

审批流转

更新当前步骤与申请状态，并根据流程分支按需创建下一批待办步骤。

5

流程结束

通过后落地证券池状态；驳回或终止只结束申请和步骤，不改变当前池状态。

关键结论：系统没有独立的通用流程实例表。ip_adjust_log 承担申请实例，ip_adjust_step 承担步骤实例，ip_pool_status 保存最终生效的证券池状态。

主页面证券查询逻辑

主页面先定位需要调库的证券，再进入详情页加载池状态、可调池和历史流程。

接口 POST /api/v1/securityPoolAdjust/querySecurityPage · querySecurityTypeList SecurityPoolAdjustService.querySecurityPage

请求与分页

  • 筛选字段：securityCode、securityShortName、securityType、issuer。
  • 证券类型下拉来自 POST /api/v1/securityPoolAdjust/querySecurityTypeList，关联 rrs_securityinfo 与 dict_security_type，与列表同口径：仅 category_type=bond，并排除 crmw（字典归 bond）及已删除态；company 本就非 bond，无需再排。
  • 分页字段：pageIndex、pageSize。
  • 初始化走 applyUrlSecurityOrList：URL 带 securityCode（事宜「去调库」等）时写入筛选并进入该券详情；无参数才只加载列表。
  • 查询、重置、切换页码或每页条数都会重新调用接口；新查询回到第 1 页。
  • 后端使用 PageHelper.startPage，返回 records 和 total。

SQL 与返回数据

  • 主表为 rrs_securityinfo。
  • 内连接 dict_security_type 取名称，并限制 category_type=bond（本页仅债券；股/基等走其它入口）。
  • 证券代码、简称、发行人均使用包含式模糊匹配：LIKE %条件%；证券类型为精确匹配 si.security_type = #{securityType}。
  • 候选证券查询无固定 ORDER BY（与需求 04「列表无固定排序」一致），分页结果顺序不作保证。
  • 固定排除 security_type = 'crmw'（凭证字典大类为 bond，须单独挡）；主体 company 已由大类过滤。
  • 固定排除退市：si.security_status IS NULL OR si.security_status != 'D'（NULL 视为未退市，避免临时代码占位未写状态时被滤掉）。
  • 与禁投池「旗下债券数量」主数据统计同口径；对比时证券池侧按发行人名称模糊筛，禁投侧按主体代码 issuer_code精确关联。
  • 主列表在操作列前由前端展示是否类字段（后端 SELECT si.* 已带回原始标志，不做中文映射）：是否担保（guarantFlag=1）、是否含权（inrightFlag=1）、是否永续（yxFlag=1）、是否私募（发行方式或内部分类含「私募」，对齐 isPrivateBond）、是否ABS（absFlag=1 或证券类型 abs/abn）、是否次级（cjFlag=1）。展示「是/否」Tag；详情页证券基本信息不增加这些字段。
1. 输入条件证券代码、简称、证券类型或发行人，可留空查询全部。
2. 开启分页PageHelper 拦截紧随其后的 Mapper 查询。
3. 查询证券证券主表关联证券类型字典并执行模糊过滤。
4. 点击“调库”以 windCode 进入详情视图并并发加载业务数据。

当前所在池查询逻辑

接口同时返回“当前证券所在池”和“同发行主体所在池”，两者用途不同。

接口 POST /api/v1/securityPoolAdjust/querySecurityPoolStatus SecurityPoolAdjustService.querySecurityPoolStatus

证券当前所在池

  1. 按请求中的 securityCode 查询 ip_pool_status。
  2. 只认 audit_status='20' 且 is_deleted=0 的有效状态。
  3. 关联未删除的 ip_investment_pool。
  4. 通过 NOT EXISTS 排除仍有子节点的池，只返回叶子池。
  5. 返回目标池、池类型、批次、调库记录和入池日期。

发行主体当前所在池

  1. 先从 rrs_securityinfo 找出当前证券的发行人。
  2. 再查询同发行人的所有证券在 ip_pool_status 中的有效池状态。
  3. 同样只返回叶子池，并按目标池分组。
  4. 返回最早入池日期、最新批次号，以及主体在该池的证券数量 bondCount。

池名称回填

Service 加载全部投资池的“父级 / 子级”全路径名称映射，覆盖 SQL 返回的单级池名，使页面能够直观看到完整层级。

前端用途

securityCurrentPools 用于决定哪些池可调出、哪些池不能重复调入；issuerCurrentPools 用于展示主体整体的在池情况和辅助业务判断。

可调入 / 可调出库查询逻辑

对应详情页左右两栏「可调入库」「可调出库」。整段以 queryAdjustPoolList 为准：先查、再滤、前端再按是否已在池筛成两边。下面按代码执行顺序写。

接口 POST /api/v1/securityPoolAdjust/queryAdjustPoolList SecurityPoolAdjustService.queryAdjustPoolList

1. 页面怎么看、何时查

  1. 进入某只证券的调库详情后，左右两栏分别是可调入库、可调出库。列：投资池名称、上限数量、现有数量；可调入库末级池还可选信评报告 / 其他材料。
  2. 只有末级池能勾选（有下级的节点不能勾）。勾选时若与已选池互斥，自动取消先选的冲突项并提示。
  3. 进入详情时并发请求两次本接口：一次 adjustDirection=in（带当前「是否放开规则」），一次 adjustDirection=out。同时查证券详情、当前所在池、调库记录。
  4. 页面上切换「是否放开规则」后，只重查 in 这一次；已勾但不在新结果里的调入项会被清掉。
  5. 可调入库结果出来后，若其中含信用债 1～5 级，会按池预填近 6 个月最近一条信评报告（该级尚无手工选择时才填）。

2. 请求参数

字段 含义
securityCode 当前证券代码。调入过滤信用债 1～5 级时必用；为空则不做信用债 1～5 级那套过滤。
adjustDirection in = 可调入库（会过滤信用债 1～5 级）；out = 可调出库（不做信用债 1～5 级过滤）。
currentUserId 当前登录用户。空或不合法直接报错。值为 1 视为管理员，不做人员权限过滤。
releaseRules 是否放开规则。页面「是」传 true：调入时跳过信用债 1～5 级矩阵过滤。仅 in 有意义。

3. 后端主流程（按执行顺序）

方法：queryAdjustPoolList。任一步滤空则返回空列表。
  1. 查 ip_investment_pool，条件仅 is_deleted=0，按 outer_sort / parent_id / inner_sort 排序。本接口不按 status=enabled 再筛一层。
  2. 人员权限：管理员 currentUserId=1 不过滤。普通用户查「可调整」权限（ip_pool_permission.permission_type=adjustable）：处理人是本人，或处理人是其启用角色。命中的池及其全部上级都保留，方便页面按层级展示。一个权限都没有则返回空。
  3. 排除 CRMW 池：pool_type=crmw 的入、出都去掉（CRMW 走独立链路）。禁投、观察、黑名单、重点观察等不在这一步排除，单券仍可调这些池。
  4. 仅 adjustDirection=in：再走第 4 节「调入过滤信用债 1～5 级」。out 跳过。
  5. 查全部调入互斥（in_mutex）、调出互斥（out_mutex），按池 ID 挂到返回对象上。
  6. 汇总各池当前有效在池数量（ip_pool_status 审批通过且未删除），写入 currentCount；maxCapacity 取池配置。
  7. 转成 PoolDto 列表返回（扁平，带 parentId）。

4. 调入过滤信用债 1～5 级（按执行顺序）

方法：filterInboundByGradeRule。只处理信用债 1～5 级（pool_type=credit_bond 且 inner_sort 1～5）。其它池原样留下。前面步骤命中「结束」则不再往后。调出不走本节。
  1. releaseRules=true 或没有证券代码：不过滤，信用债 1～5 级原样返回（结束）。
  2. 当前列表里没有任何信用债池：结束。
  3. 按证券代码查不到证券主数据：结束。
  4. 证券类型是可转债 / 可交换债 / 可分离转债 / CRMW：信用债 1～5 级全部不显示（结束）。
  5. 证券或发行主体在重点观察，当前未在信用债 1～5 级，且不是强担保（有担保且担保人内评 1 档）：信用债 1～5 级全部不显示（结束）。已在 1～4 级的，第 11 步只留五级。
  6. 取主体内评分档：正式证券读 innerIssuerRating；临时代码无内评默认 4；担保债再和担保人内评取孰高（用来查矩阵的档，不是再降一级）。
  7. 正式证券仍无内评：信用债 1～5 级全部不显示（结束）。
  8. 匹配期限档：普通债用 date_exists（天÷365）；含权债回售按行权期限、赎回按到期剩余期限，两者都有取更短；期限为空默认最长档（期限>5 / GT_5），不跳过。
  9. 用第 6 步内评档 × 第 8 步期限档查矩阵，得到允许的信用债级别，并算出标准最好档。
  10. 决定各信用债级别是否保留：
    • 永续，或私募 / ABS / 次级且内评不是 1 档：标准最好档至少下调 1 级，然后保留该级到五级。矩阵只给 1 级 → 显示 2～5；最好档是 2 → 显示 3～5。
    • 其余（普通债、1 档私募/ABS/次级、担保债、含权债、观察名单）：矩阵给哪几级就保留哪几级。匹配 2、3 只显示 2、3；匹配 1 只显示 1。
  11. 重点观察且已在 1～4 级：只保留五级；已在五级不可再上调。
  12. 期限档匹配不上（没有启用档，或算出的年数落不进任何档）：信用债 1～5 级不显示，不放开。
  13. 非信用债 1～5 级的池全部保留；某级被保留时，其上级（如信用债大库）一并保留，便于按层级展示。

5. 返回字段

字段 含义
id / parentId / poolName / poolCode 池主键、上级、名称、编码。前端靠 parentId 拼层级。
poolType / poolLevel 池类型、层级。
maxCapacity / currentCount 上限数量、现有数量。页面只在末级池展示。
inMutexPoolIds / outMutexPoolIds 调入互斥、调出互斥的对方池 ID。勾选时用来自动取消冲突项。

6. 前端再筛成可调入库 / 可调出库

  1. 先用 querySecurityPoolStatus 得到该券当前有效在池 ID（audit_status=20 且未删除的末级池）。
  2. 可调出库：在 out 结果里，只留「当前已在」的池，以及这些池的上级。没有在池记录则右栏为空。
  3. 可调入库：在 in 结果里去掉「当前已在」的末级池，避免重复调入；某个上级若全部下级都已在池，该上级也不再显示。
  4. 按 parentId 组装成带下级的列表给表格展示，默认全部展开。只有没有下级的行能勾选。
  5. 调入、调出两边的互斥 ID 合并后，勾选时跨栏也会互斥替换。
选池第 4 节与提交时的 inCheckMainGradeRule 同一套口径：选不中的信用债 1～5 级，校验也不该过。

调入 / 调出校验逻辑

用户点击“下一步”后，前端把勾选的叶子池提交给后端；后端返回手工项、联动项、互斥项及每项失败原因和候选流程。

接口 POST /api/v1/securityPoolAdjust/checkAdjust SecurityPoolAdjustService.checkAdjust
1. 请求校验证券代码和调库项不能为空。
2. 共享数据初始化集中加载证券、池、当前状态、关系和进行中流程。
3. 方向规则校验分别执行调入和调出规则，收集全部失败原因。
4. 匹配审批流程只为校验通过的手工项返回可选择流程。

调入校验（通用 + 类型特有）

  1. 通用（顺序与 checkCommonIn 一致）：池锁定 → 品种 → 市场 → 进行中流程（pending）→ 是否已在目标池 → 容量 → 来源池 → 调入限制池（in_restrict）→ 本次是否同时调入互斥池 → 弹性禁投池（in_soft_restrict，警告不阻断）→ 全局禁止池（禁投池，forbidden）→ 行业限制（已注释）→ 开放日。
  2. 债券（顺序与 checkBondIn 一致）：到期校验 → 主体内评×期限矩阵，口径与上方第 4 节同一套。
  3. 股票（顺序与 checkStockIn 一致）：退市校验 → 股票入池评级限制（入口保留，当前空实现不拦截，未接 investrank）。
  4. 基金（顺序与 checkFundIn 一致）：基金评分（仅 check 阶段按请求 fundRate 校验；正式提交不携带 fundRate、不再次校验）。
  5. 主体 company：类型特有校验暂无（调入不校验到期）。
  6. 报告必填（in_report_restriction）在提交阶段校验；豁免口径：半年内同主体已有审批通过调入且确有报告（queryHasRecentInboundWithReport / bondfileflag 语义），非「任意有效报告」。

调出校验（通用 + 类型特有）

  1. 通用（顺序与 checkCommonOut 一致）：池锁定 → 进行中流程（pending）→ 证券是否确在目标池 → 冻结期 → 调出限制池（out_restrict）→ 调出互斥池（out_mutex）→ 本次是否同时调出互斥池 → 弹性禁投池（警告不阻断）→ 开放日。
  2. 债券/股票：到期或退市等类型特有规则；报告必填在提交阶段按调出报告限制（out_report_restriction）校验。

自动生成联动 / 互斥 / 关联码

  • 调入目标池时，调入联动池（in_linked）自动生成联动调入项。
  • 调入目标池时，若证券已在调入互斥池（in_mutex）中，自动生成该池的互斥调出项。
  • 调出目标池时，调出联动池（out_linked）自动生成联动调出项。
  • 多市场关联码（同一证券多市场代码）可同批调库：关联项独立校验在池/容量等，与主券共用批次与流程。
  • 使用「池 ID + 方向」去重；用户手工项优先于自动项。
  • 手工项失败时，同组自动联动/互斥项继承阻断状态。
  • 反阻断：同组互斥配套调出失败时，反阻断同组手工调入，避免只入目标池形成双池。

候选流程匹配

顺序与 resolveAdjustFlowOptionsForItem 一致（仅 canAdjust 的手工项）。

  • 调出 → 目标池标准调出流程（outFlow）。
  • 调入 → 若当前已在目标池 in_mutex 互斥池中：优先特殊审批（bond:special-inbound）；信用债大库（pool_type=credit_bond）默认排除特殊审批。
  • 调入 → 目标池非信用债大库：默认调入（inFlow）。
  • 调入 → 已在信用债大库：同父级按 innerSort 上调 / 下调流程。
  • 调入 → 不在信用债大库：同时评估白名单 / 简易 / 默认调入，推荐优先级 白名单 > 简易 > 默认。
  • 白名单条件顺序：剩余期限≤3年 → 非永续/私募/ABS → 债券类 → 主体在白名单池（WHITELIST_POOL_IDS 当前为空，本条件固定不成立）→ 非担保债。
  • 简易条件顺序：目标池为一/二/三级信用债库 → 剩余期限可解析（date_exists）→ 不超过同主体在池最大期限 → 180 天内一般流程入过目标池 → 主体/展望未下调或下调时担保人未下调（已注释）。
当前实现说明： 校验结果带 failReasons 与 warnings；前端「调整说明」失败时分条展示「未通过（共 N 项）」+ 编号列表（保留全部 failReasons，检查项文案不含「无法调入」终局语气）；警告单独展示。同组（同一 adjustGroupKey）手工+联动/互斥行用底色区分。 评级下调由 RatingDowngradeChecker 查 wind（主体比较 creditrating/precreditrating，展望读 rating_outlook 是否负面，担保人由前端下拉传 guarantorCode）；简易流程末项「评级下调判断」已注释，但取值仍计算保留。 文中「已注释」「空实现」「当前为空」等与源码一致，顺序与 checkCommonIn / checkCommonOut 调用顺序一致。

校验分层（check / submit / 终审）

  • checkAdjust：全量通用+类型规则、联动互斥扩展、流程候选；行业调用已注释；基金评分仅此阶段（依赖请求 fundRate）。
  • submitAdjustLog：不整单再调 checkAdjust。提交专属：字段合法性、防重复、报告必填、互斥配套调出必须成功、pending 池组；直通项再走下方 recheck 子集后落池。
  • recheckBeforeFinalApproval（直通与最终审批共用）：锁目标池后只跑动态子集——调入：池锁 / 已在目标池 / 品种 / 来源 / 限制 / 全局禁投 / 容量（含同批增量）；调出：池锁 / 未在目标池 / 限制 / 冻结期。不再跑：开放日、行业、基金评分、内评矩阵、市场、pending、同请求互斥、弹性警告、到期/退市等静态或 check 专属项。

提交申请与审批推进逻辑

校验只判断“能不能调”；提交才创建申请和步骤，审批结束才决定是否真正改变池状态。

提交申请：五阶段

  1. 前置校验：证券代码、调整人、调库项等字段合法性；防重复提交；不在此重跑全量 checkAdjust。
  2. 参数初始化：加载证券、池关系、当前状态及每个唯一流程的运行快照；同一次提交统一 submit_time，保证同批历史聚拢。
  3. 调入处理：按池报告限制校验报告必填；校验 pending 池组与互斥配套调出；按调库组写入手工/联动/互斥/关联码记录并绑定附件。
  4. 调出处理：按出库报告限制校验；同样写入申请记录并保持同组批次关系。
  5. 后续处理：合并主档与页面可编辑字段后写 ip_adjust_security_snapshot（不修改 rrs_securityinfo 主档）；直通项再 recheckBeforeFinalApproval 后落池。

直通与人工审批

  • 无流程或流程为 start → end 时视为直通。
  • 直通：先锁池并 recheckBeforeFinalApproval（动态子集，见上「校验分层」），再写或逻辑删除 ip_pool_status（与最终审批同一套保护）。
  • 非直通：申请记为流程中（audit_status=00），创建开始、提交人和首个待审批步骤。
  • 后续节点采用懒创建，审批到达时再写入 ip_adjust_step。
  • 仅 audit_status=20 落地池状态；驳回/撤回等不改当前在池。

审批动作

  • 接口：POST /api/v1/securityPoolAdjustFlow/submitAdjustAudit（带附件走 submitAdjustAuditWithFiles）。
  • 先校验步骤仍为待处理并确认实际处理人；发起人不能参与后续流程操作（管理员除外）。
  • 管理员代办时优先定位到管理员自己的待处理步骤，处理意见后追加「（由管理员操作）」标识。
  • 更新当前步骤动作、意见、处理人和处理时间。
  • 会签节点等待全部人员处理；抢占节点处理后将其他待办标记为跳过。
  • 重新读取节点、连线和条件规则，按动作寻找下一节点。
  • 驳回待修改节点提交时支持附件增删与报告附件复制（submitAdjustAuditWithFiles + attachmentChanges）。

结束落库

  • 通过：同批申请更新为通过，调入新增池状态、调出逻辑删除池状态。
  • 评级联动改判：审批通过时可携带 redirectPoolId 改判目标池，queryRedirectPoolOptions 提供矩阵允许的候选池，finishAdjustBatch 校验改判池须在允许列表内并更新调入日志目标池。
  • 驳回或终止：结束申请和步骤，但不改变 ip_pool_status。
  • 通过后若存在手工上传信评附件，生成 rrs_report_in 并复制附件。
  • 修改节点重新提交时，可增删并重新绑定调库附件。

完整表清单

“条件触发”表示并非每笔调库都会访问或写入；事件表和仅用于流程设计维护的配置表不纳入运行口径。

序号 表名 用途 读写 触发场景
A. 核心业务与校验表
1ip_adjust_log 核心 调库申请明细和批次记录，保存证券、目标池、调整方向、流程及审批状态。 查询新增更新 提交调库时新增；审批时更新状态；详情、待办、历史记录和批次结束时查询。
2ip_adjust_step 核心 流程运行步骤，保存节点、处理人、动作、意见和处理时间。 查询新增更新 发起后创建开始、提交和首个审批步骤；审批过程中更新当前步骤并创建后续步骤。
3ip_pool_status 核心 证券当前所在投资池状态，是调库最终生效结果。 查询新增逻辑删除 校验当前池状态和容量；流程通过后，调入新增、调出逻辑删除。
4rrs_securityinfo 证券基础信息，包括代码、名称、发行人、证券类型和评级等。 查询 证券搜索、详情、主体池校验及报告生成；本模块只读主档，不更新证券信息（可编辑字段实际写入 ip_adjust_security_snapshot）。
5ip_adjust_security_snapshot 调库证券信息快照，按调库日志保存提交时的可编辑证券字段。 查询新增 提交/重提时按调库日志写入可编辑证券信息快照；详情页按 adjustLogId/windCode 读快照整包回显。
6ip_investment_pool 投资池定义、层级、容量、池类型及绑定的调入/调出流程。 查询 加载可调池、构建池树、校验容量、获取目标池和推荐流程。
7ip_pool_relation 投资池之间的联动和互斥关系。 查询 调库校验和提交时，根据关系生成联动调整、互斥调整明细。
8ip_pool_permission 投资池可调权限配置，支持按用户或角色授权。 查询 进入调库页面、查询可调池时判断当前用户是否有权限操作目标池。
9dict_security_type 证券类型字典及证券大类信息。 查询 证券列表展示类型名称；流程通过后生成内部报告时判断报告类型。
B. 审批流程配置表
10wf_flow_definition 流程定义，保存流程名称、Key、类型和启停状态。 查询 校验候选流程、提交时确认选定流程、审批推进时恢复流程上下文。
11wf_flow_version 流程版本，确定当前生效的流程版本。 查询 发起时读取 active 版本；审批流转时根据当前节点恢复版本。
12wf_flow_node 流程节点，包括开始、审批、自动和结束节点。 查询 创建初始步骤、定位当前节点、查找下一节点和创建结束步骤。
13wf_flow_edge 流程节点之间的有向连线。 查询 提交和审批时计算主路径、通过分支、驳回分支及下一节点。
14wf_edge_cond_rule 流程连线条件规则。 查询 审批过程中存在条件分支时，按处理动作匹配应走的连线。
15wf_node_approval_config 审批节点策略，如发起人、会签和抢占策略。 查询 生成审批步骤、判断节点完成条件以及同节点其他待办是否跳过。
16wf_node_approval_handler 审批节点处理人配置，可配置具体用户或角色。 查询 创建待办步骤时，将节点配置解析成具体审批人员。
C. 用户与角色表（ais_inv_analysis 库）
17ais_inv_analysis.t_sys_user 系统用户信息。 查询 审批节点按角色配置时，将角色展开成具体处理人。
18ais_inv_analysis.t_sys_role 系统角色及角色层级。 查询 权限校验以及递归解析审批角色和子角色。
19ais_inv_analysis.t_sys_user_role 用户与角色关联关系。 查询 查询发起人的投资池权限；把审批角色展开为具体用户。
D. 附件与报告表（条件触发）
20sys_attachment 条件触发 调库信评报告、其他材料和报告库附件元数据。 查询新增更新 上传附件、引用已有报告附件、修改节点增删附件，以及流程通过后的附件复制。
21rrs_report_in 条件触发 内部研究报告。 查询新增 发起时选择内部报告；审批通过且存在手工上传信评附件时，新增内部报告。
22rrs_report_out 条件触发 外部研究报告。 查询 发起调库时打开外部报告列表并选择已有报告附件。

核心表关系

以下不是数据库物理外键，而是业务代码按照 ID、批次号和证券代码维护的逻辑关系。

申请与步骤

  • ip_adjust_log.id 对应 ip_adjust_step.adjust_log_id
  • adjust_batch_no 聚合同批手工、联动和互斥调整
  • 一个审批节点按处理人展开后可能产生多条步骤

申请与目标池

  • ip_adjust_log.target_pool_id 对应投资池 ID
  • 审批通过后按调整方向写入或逻辑删除 ip_pool_status
  • 池关系用于扩展联动与互斥调整明细

步骤与流程定义

  • ip_adjust_step.flow_node_id 指向流程节点
  • 节点归属于版本，版本归属于流程定义
  • 节点连线和条件规则共同决定下一步骤

流程结束分支

通过与未通过的最大区别，是是否真正改变证券池状态。

审批通过

更新 ip_adjust_step 和 ip_adjust_log 为完成状态；调入时新增 ip_pool_status，调出时逻辑删除对应状态。若存在手工上传的信评报告附件，再新增 rrs_report_in 并复制 sys_attachment。

驳回、拒绝或终止

更新 ip_adjust_step 和 ip_adjust_log 的处理结果及终态，不新增或删除 ip_pool_status，也不会执行审批通过后的内部报告沉淀。

口径与阅读说明

  • 完整口径共 22 张表，包含页面查询、发起校验、运行步骤、用户角色、附件和报告；信用债矩阵另读 credit_bond_pool_grade_rule / credit_bond_term_bucket。
  • 若只关注流程运行与最终落库，核心是 ip_adjust_log、ip_adjust_step、ip_pool_status。
  • audit_status：仅审批通过（20）落地池状态；流程中（00）、驳回待修改（11）、审批驳回（21）、已撤回（99）等只改日志/步骤。
  • wf_* 表保存流程模板配置，运行过程中主要读取，不写入流程设计数据。
  • *_evt 事件表用于流程设计或投资池配置变更审计，不是本次调库实例运行的写入表。
  • wf_node_auto_config、wf_node_notify_config、wf_node_condition_config 当前未被证券池调库运行服务读取。
  • 本页依据当前 Controller / Service / Mapper XML 与前端页面整理，适用于当前代码版本；规则变化须同步维护。
