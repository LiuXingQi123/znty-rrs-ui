与证券池批量调整的差异

页面 pages/stock_security_batch_adjust.html · API 前缀 /api/v1/stockSecurityBatchAdjust。

目标池与候选证券

  • 目标池：仅 pool_code=bond_product_root 子树下启用叶子（不含其它 bond_product 根如「债券产品库1」）。
  • 可选证券：来源池多选必选（下表 6 个 pool_code）；支持发行主体模糊查询；代码/简称/市场筛选同批量页。
  • CRMW 来源读 ip_pool_status_crmw；其它来源读 ip_pool_status。

渠道标签

  • 手工项 adjustType 仍为 手动批量调整（无「存量专用」类型）。
  • 无 Excel 的 clearTarget / excel_importable 语义。
  • 与 Excel 差异：本页不注入目标池 batchIn/batchOut；Excel 仍可能注入 bulk 推荐流程。

同构复用（与证券池批量一致）

编排在 Stock 服务，规则与落库在单券 SecurityPoolAdjustService。

checkAdjust · addAdjustLogWithFiles → SecurityPoolAdjustService

校验

  • 逐券转 AdjustCheckReq，调用 securityPoolAdjustService.checkAdjust。
  • 通用/类型规则、联动互斥、反阻断与单券一致（行业已注释；基金评分仅 check 且本页不传 fundRate）。
  • 流程候选完全透传单笔结果（白名单/简易/默认/特殊/升降级等），不注入、不回填 batchIn/batchOut。
  • releaseRules=yes 仅跳过内评矩阵，其它硬规则仍执行。

提交与落池

  • 整批一个事务，任一失败全部回滚；防重复提交窗口与批量同构。
  • 按触发主券分组调用 submitAdjustLog；共享附件与 BatchNoContext。multipart 同时传递与 files 同序的 originalFileNameListJson，用于保留中文原始文件名。
  • 直通：isDirectAdjustFlow + recheckBeforeFinalApproval（动态子集，见证券池调库「校验分层」）。
  • 仅 audit_status=20 落地 ip_pool_status；驳回/撤回不改在池。
  • 后续审批复用证券池调库 Flow 服务。
