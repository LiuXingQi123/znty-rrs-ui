股票池调整

从股票查询、实时基础信息、当前所在池到可调整池、调库校验及报告材料提交，说明单笔股票申请如何进入一般或快速流程。

业务流程总览

从页面操作到数据库读写的主要路径。

1. 股票查询按代码、简称、行业、市场查询股票并选择调整对象。
2. 股票与池信息加载 15 项实时信息、两次评级、当前池和可调整池。
3. 选择调整项选择调入/调出，展开联动互斥并准备报告材料。
4. 调库校验检查每个目标池、方向及关系，选择候选流程。
5. 提交并流转服务端锁定复核，写股票日志与步骤，终审 20 才落池。

主页面股票查询逻辑

股票申请独立于债券；主列表、详情与选池统一以真实股票代码识别对象。

POST /api/v1/stockPoolAdjust/queryStockPage POST /api/v1/stockPoolAdjust/queryStockTypeList POST /api/v1/stockPoolAdjust/queryIndustryList POST /api/v1/stockPoolAdjust/queryStockDetail

条件与分页

  • 页面条件为股票代码、股票简称、所属行业、市场；queryStockPage 接收对应筛选和 pageIndex / pageSize，返回 PageResult。
  • 代码、简称支持模糊匹配，行业与市场按代码过滤；类型和行业选项分别由 queryStockTypeList / queryIndustryList 提供。
  • 点击股票加载详情、当前所在池、可调整池及申请记录；切换股票后清理上一只股票的临时选池和材料状态。

SQL 与返回数据

  • rrs_stockinfo 固定未删除、上市状态 L，关联未删除的股票品种字典；按股票代码升序分页。
  • 评级按 rating_date DESC, id DESC 取最近两次未删除记录；buy / overweight / neutral / underweight / sell 分别展示买入 / 增持 / 中性 / 减持 / 卖出，无评级留白。
  • 详情展示 15 项基础信息：股票简称、股票代码、所属行业、市场、昨收、最高、最低、平均、换手率、交易总量(手)、交易市值(万)、总股本(百万)、总市值(百万)、流通A股(百万)、A股市值(百万)。
  • 基础信息实时读取 rrs_stockinfo；空值留白，零值正常显示。换手率原值 1.25 展示 1.25%，不再乘 100；交易市值为当日成交金额，币种跟随市场；港股交易量按来源的“手”展示。
  • 市场 SSE / SZSE / HKEX 和评级由前端字典转换，枚举使用标签；后端返回 code，不写中文映射。

当前所在池查询逻辑

有效池状态、计划调整项和历史申请分别查询，不把在途申请当作已生效成员。

POST /api/v1/stockPoolAdjust/queryStockPoolStatus POST /api/v1/stockPoolAdjust/queryAdjustLogList POST /api/v1/stockPoolAdjust/queryAdjustStepList

当前有效池状态

  • queryStockPoolStatus 按股票代码查询 ip_pool_status_stock，仅 audit_status=20 且未删除，按入池时间和主键倒序。
  • 返回当前所在池、入池时间、关联日志和完整池路径；用于展示现有成员、调出选择与冻结期判断。
  • queryAdjustLogList 优先按批次查询；无批次/日志定位时仅查未结束申请，排除 -1 / 20 / 21 / 99。步骤查询同样优先使用批次。

计划调整池与前端用途

  • 本次选池仅构成计划项，提交前可以移除、重新校验；只有审批通过才会更改有效池状态。
  • 来源池按 OR：当前有效成员或同一调整组计划调入任一来源即可；其他批次在途调入不能当作来源。
  • 通过当前池与计划项区分“已经在池”“准备调入”“准备调出”；同一股票同一目标池的重复或相反申请由服务端阻断。

可调入 / 可调出池查询逻辑

先取得当前用户可调整的股票池层级，再按方向选择目标池；最终以服务端校验为准。

POST /api/v1/stockPoolAdjust/queryAdjustPoolList

触发时点与输入参数

  • 选择股票、切换方向或刷新选池时调用 queryAdjustPoolList，传 stockCode / currentUserId / adjustDirection。方向使用 in/out。
  • 服务端核实股票市场，结合启用池、支持股票的投资品种与市场以及用户/角色调整权限筛选，并保留必要祖先节点。
  • 股票仅支持上交所、深交所及港交所；品种字典必须属于 stock，不能拿债券或基金代码进入股票链路。

返回字段与方向筛选

  • 返回树层级、池名称、有效成员数量及互斥池标识等信息；祖先仅组织结构，实际调整选择业务叶子池。
  • 前端结合方向和当前所在池提供可选项；调入拒绝已有效在池，调出要求当前有效在池。
  • 树上的可选状态不能替代提交权限：锁定、容量、最新评级、开放日、冻结期、报告与来源关系等在校验及提交时继续复核。

调入 / 调出校验逻辑

逐项校验后返回完整调整组及候选流程；主项、联动、互斥、限制项明确区分。

POST /api/v1/stockPoolAdjust/checkAdjust POST /api/v1/reports/queryInReportPage POST /api/v1/reports/queryOutReportPage

调入校验

  • 核实股票存在、未删除、已上市且未退市，市场支持；目标池启用、未锁定，投资品种/市场匹配，当前用户有调整权限。
  • 检查行业、最新评级、容量、当前成员及在途申请、来源池和开放日；已有效在目标池不能重复调入。
  • grade_astrict 为空不限制；非空仅接受五种股票评级代码，无评级或不匹配失败，未知配置明确报错。容量按有效成员核算。

调出校验

  • 复核主档、目标池状态、市场品种和权限，必须存在有效成员，不能存在冲突在途申请。
  • 检查开放日、冻结期、调出限制、来源/关系及报告要求；页面显示当前池不代表一定可立即调出。
  • IN_RESTRICT / OUT_RESTRICT 为硬性阻断；IN_SOFT_RESTRICT / OUT_SOFT_RESTRICT 显示警告，并非强制失败。

联动、互斥与来源规则

  • checkAdjust 传股票、用户及 items 中的目标池、方向、项标识和调整组；服务端展开联动调入、互斥调出等关系项。
  • 同一组来源池按 OR 判断，允许该组计划调入作为来源；主项失败阻断所属关系组，失败关系保留具体原因供页面展示。
  • 同股票同池去重并拦截相反方向；硬性限制与在途防重不能通过删除客户端关系项绕过。

候选流程、报告与分层复核

  • 校验返回 flowOptions；单笔默认推荐 normalInbound / normalOutbound，配置允许时可选 fastInbound / fastOutbound。
  • 报告要求按 none / any / internal 核实；报告必须属于股票业务且代码匹配。内部/外部报告目录筛选与本地文件均需核验。
  • 前端校验便于选择与提示，提交时服务端再次校验；最终审批通过前按最新数据整组复核，不能仅信任之前的通过结果。

提交保存与流程推进逻辑

先完成本次申请的所有复核，再写日志、附件及步骤，任一失败整体回滚。

POST /api/v1/stockPoolAdjust/addAdjustLog POST /api/v1/stockPoolAdjust/addAdjustLogWithFiles

请求、报告与材料

  • 提交 stockCode / adjustType / adjustReason / adjustAdvice / adjusterId / adjusterName / items，条目包含目标池、方向、项标识、组、流程 ID/key/type 及报告索引。
  • 页面原因建议最多 500 字，接口最多 1000 字；必填项及候选流程选择按页面与服务端要求检查。
  • 无新文件调用 addAdjustLog，有文件调用 addAdjustLogWithFiles；multipart 携带请求 JSON 与原始文件名，禁止直接信任客户端附件归属。
  • 报告/材料分类为 stock_report_hand/in/out、stock_material_hand/in/out，绑定主表固定 ip_adjust_log_stock，同 ID 与债券、基金隔离。

事务、流程与落池

  • 按稳定顺序锁股票与目标池，重新准备全部调整项，复核关系、容量、权限、评级及报告后写入。生成 STOCK 批次和每池日志。
  • 先建立整组日志、绑定文件，再启动主项选定流程；关系项随主项，创建股票专属步骤并记录流程版本节点。
  • 一般流程进入人工待办；快速流程若到达结束，也必须最终复核通过后才将本组置为 20 并落池。
  • 失败回滚本次日志、步骤和附件绑定，清理本次新增物理文件，不能保留已生效的部分调整。

核心表关系

业务配置、申请留痕、运行步骤与当前状态各有明确职责。

调整日志与步骤

  • 一组股票申请共享 adjust_batch_no，每池一条 ip_adjust_log_stock；ip_adjust_step_stock 保存待办和操作记录。
  • 名称、行业、最近两次评级保存提交时留痕，基础行情不做整份快照。

当前池与版本配置

  • ip_pool_status_stock 是当前有效状态，日志审批状态不是当前池记录。只有 20 写入或逻辑移除当前成员。
  • 运行步骤引用所属流程版本节点；后续审批按节点版本读取配置，发布新版本不改变既有申请。

流程结束分支

结束动作区分通过、驳回和撤回，只有通过影响当前池。

正常通过

  • 整组复核主档、池配置、市场品种、权限、行业评级、关系、开放日、冻结期、容量及报告，全部通过后统一更新日志 20 并应用入/出池。
  • 提交或终审前配置变化可能使申请失败，不能将旧校验快照当作最终授权。

驳回、修改与撤回

  • 驳回路由可进入 11 待修改，也可结束为 21；发起人按流程修改后重提，撤回结束为 99，均不更新有效池。
  • -1 无效 / 00 流程中 / 11 驳回待修改 / 20 审批通过 / 21 审批驳回 / 32 自动处理预留 / 99 发起人已撤回；仅 20 更新当前池状态。

关键规则与当前实现说明

与当前股票业务实现一致的状态、权限及数据边界。

  • 股票、债券、基金流程结构相近，但股票日志/步骤/当前池表与业务域独立，禁止用其他域日志 ID 查询或绑定附件。
  • 来源池 OR、整组关系与报告要求在校验、提交、终审保持同一口径；同组计划来源允许，其他批次在途来源不允许。
  • 股票主档和评级用于实时展示，日志只留名称、行业、两次评级；历史不能由最新资料覆盖。
  • 申请页负责查询、校验和提交；审核及详情的 PDF、附件修改、会签和返回行为见对应审核与详情文档。
